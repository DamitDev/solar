# Solar — server-side routing state branch progress

## US-001 — Instance state Redis store (DONE)

Added `app/redis_state/instance_states.py` exposing `InstanceStatesStore`
with `set`/`get`/`delete`/`get_all` keyed by `host:instance` (prefix
`solar:istate:`), storing the `InstanceStatePayload` shape
(`{host_id, host_name, instance_id, timestamp, data}`). Each write issues a
TTL (`ISTATE_TTL_S = 300`) so a host that stops reporting expires its recorded
state. Registered on `app/redis_state/__init__.py` as `instance_states_store`
and exported in `__all__`.

Write paths wired at both relay choke points in
`app/socketio_app/host_handlers.py`:
- `host_instance_state` (single-event emitter)
- `host_instance_state_batch` (batched emitter, per-entry via
  `asyncio.gather` alongside the WS emit)

Tests:
- Unit: `tests/test_instance_states.py` (7 tests) — dict-based fake Redis,
  patches the store's own namespace, asserts set/get values, delete, that a
  TTL is issued on write (default + custom), and get_all.
- Integration: `tests_integration/infrastructure/test_instance_state_ttl.py`
  — round-trips a real write against the live session Redis with a short TTL
  and confirms expiry after the TTL while a long-TTL sibling survives.
- `solar:istate:` added to the volatile-redis flush list in
  `tests_integration/conftest.py::_flush_volatile_redis`.

Feedback loops: ruff + black pass, full solar-control unit suite green
(1021 passed). Integration suite requires Docker; collected/compiled cleanly
but not executed here.

## US-002 — Active request Redis store (DONE)

Added a per-request active registry to `RoutingStore` in
`app/redis_state/routing.py` (prefix `solar:active-req:`), the server-authoritative
source for the WebUI's active-request view:
- `create_request` — records an in-flight request on `request_start`
  (model/endpoint/client_ip/timestamp)
- `update_request` — merges routing details on `request_routed`/`request_reroute`
  (host_id/host_name/instance_id/resolved_model/attempt), returns None if the
  request is unknown
- `delete_request` — removes the entry on `request_success`/`request_error`
- `get_request` / `list_requests` — read individual or all live entries
  (used by snapshotting in later stories)

Each write issues a TTL mirroring `ACTIVE_TTL_S` (300 s, overridable per-write)
so a replica that crashes mid-request expires its entry instead of showing a
stuck 'processing' request. Cross-pod delete semantics fall out naturally from
shared Redis: a terminal event on any replica removes the key regardless of
which replica created it.

Writes wired at the single broadcast choke point in
`app/gateway.py::_broadcast_routing_event`, which now branches on
`event_data.type` and dispatches to the new `_update_active_registry` helper.
Registry-update failures are swallowed so a Redis hiccup never breaks the
actual event broadcast/logging.

Tests:
- Unit: `tests/test_routing_registry.py` (7 tests) — dict-based fake Redis,
  patches the store's own namespace, asserts create/update/delete lifecycle,
  custom TTL on write, cross-pod delete semantics (two store instances), and
  list_requests excluding deleted/expired.
- Integration: `tests_integration/infrastructure/test_routing_registry_ttl.py`
  — round-trips a real write against the live session Redis with a short TTL,
  confirms expiry after the TTL while a long-TTL sibling survives, and that a
  terminal delete removes the entry.
- `solar:active-req:` added to the volatile-redis flush list in
  `tests_integration/conftest.py::_flush_volatile_redis`.

Feedback loops: ruff + black pass, full solar-control unit suite green
(1028 passed). Integration suite requires Docker; collected/compiled cleanly
but not executed here.

## US-003 — Snapshot builder service (DONE)

Added the typed, versioned snapshot payload model and its builder:

- `app/models/routing_snapshot.py` — `RoutingSnapshot` + sub-models
  (`RoutingHost`, `InstanceStateEntry`, `ActiveRequestEntry`,
  `RequestAggregates`) with `schema_version` (1) and `generated_at`. The same
  payload is shared by the WS emit (US-004) and REST mirror (US-005).
  Field contract to the WebUI (documented in the module docstring):
  `active_requests` → requests Map, `instance_states` → instanceStates Map,
  `endpoints` → endpoints list, `aggregates` → server-computed inFlight/totals,
  `hosts`/`pending_hosts` → host status + pending-approval hosts. Exported via
  `app/models/__init__.py`.
- `app/services/render_state.py` — `build_routing_snapshot()` composes
  hosts (status + drain + health + instance cache from `host_store`),
  per-instance states (`instance_states_store.get_all`), active requests
  (`routing_store.list_requests`), server-computed tallies, endpoints
  (`endpoint_db.get_all_endpoints`, shape matches `endpoints_update`), and
  pending hosts (`host_store.get_all_pending`).
- Aggregate arithmetic moved server-side (mirrors WebUI `workload.ts` /
  `graph.ts`): `by_instance` (`host:instance` cell keys), `by_host`,
  `by_model` (uses `resolved_model` with `model` fallback), `by_endpoint`,
  plus `queued`/`processing` (an entry carrying host+instance is
  `processing`, otherwise `queued`) and `errored` (0 — terminal requests are
  deleted from the registry). Endpoint loading degrades to empty on failure.

Tests: `tests/test_render_state.py` (7 tests, anyio) — placeholder-shaped
snapshot, host status/drain/health + connected + instance cache, instance
state data/timestamp, tallies by instance/host/model/endpoint, unrouted
request counting as queued, resolved_model fallback, endpoints + pending
hosts pass-through.

Feedback loops: ruff + black pass, full solar-control unit suite green
(1036 passed).

## US-004 — Connect snapshot event (DONE)

`solar-control` now emits the authoritative `routing_snapshot` to a freshly
connected WebUI client before any request/instance deltas flow, so a
late-joining or reconnecting client always reconciles against fleet state
instead of a stale/partial base.

In `app/socketio_app/webui_handlers.py::webui_connect`, immediately after
`initial_status` and before the `instances_update`/`host_pending` deltas, the
handler builds the snapshot via the US-003 builder
(`build_routing_snapshot()`) and emits it to the connecting `sid`:

- Emitted payload is `snapshot.model_dump()` of the same `RoutingSnapshot`
  produced by `build_routing_snapshot()`.
- Connection-filtered emit (`to=sid`) keeps other clients unaffected.
- Ordering guarantees: `initial_status` → `routing_snapshot` →
  `instances_update`/`host_pending`, so the snapshot always precedes the deltas.

Tests:
- New `tests/test_webui_snapshot.py` (2 tests, anyio) patches the emit surface
  and verifies (a) `routing_snapshot` is emitted on connect with the builder's
  payload (`schema_version`, `generated_at`, active requests, `to=sid`) and
  (b) it is emitted strictly before the `instances_update` delta.
- Updated existing `tests/test_host_status.py::test_webui_initial_status_includes_active_jobs`
  to patch `build_routing_snapshot` (the connect handler now calls it).
- Ruff + black pass; full solar-control unit suite green (1038 passed). Ruff
  could not be executed on this NixOS machine (dynamically-linked binary stub);
  lint verified by review + black, full suite green.

## US-005 — REST snapshot mirror (DONE)

Added a REST mirror of the authoritative snapshot so the WebUI can fall back to
server state when the Socket.IO connection is down.

- New `app/routes/management/routing.py` — `GET /api/routing/state`
  (`response_model=RoutingSnapshot`), returns
  `build_routing_snapshot()` so the payload is byte-for-byte the same shape as
  the WS `routing_snapshot` event (schema_version + generated_at + all fields).
- Registered on `app/routes/management/__init__.py` via `routing.router`
  under the `/api` prefix; auth is the app-level management-key check shared by
  every management route (401 without `X-API-Key`).

Circular import fix: importing `render_state` directly exposed a latent cycle
(`render_state` → `host_handlers` → `socketio_app/server.py` →
`webui_handlers` → `render_state`). Since `render_state` only needs three
`host_handlers` helpers (`get_connected_host_ids`, `get_host_instances`,
`get_pending_hosts`) at call time, those imports were moved into the functions
that use them (`_build_hosts`, `build_routing_snapshot`) — now
`render_state` loads independently of the socketio_app package, breaking the
cycle for any entry point. `test_render_state.py` patch targets updated from
`app.services.render_state.get_*` to `app.socketio_app.host_handlers.get_*`.

Tests: new `tests/test_routing_rest.py` (2 tests) — 401 without the management
key, and 200 with the key returning the snapshot payload (schema_version,
generated_at, active_requests, hosts), patching the route's
`build_routing_snapshot` import via TestClient.

Feedback loops: ruff + black pass (ruff not executable on NixOS; verified by
review + black), full solar-control unit suite green (1040 passed).
