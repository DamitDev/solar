## Description

The WebUI Routing page builds its entire view model client-side from Socket.IO events it happens to receive (useEventStream Maps + workload.ts/graph.ts aggregations). When the tab sleeps or the socket disconnects, missed request_success / instance_state events are never replayed, so stale requests stay "processing" and load bars freeze — nothing on the server ever reconciles them. solar-control keeps no authoritative copy of instance runtime state (it relays instance_state and discards it) and no per-request active registry (only anonymous Redis counters; GatewayLogger._inflight is per-pod). This change moves the state aggregation into solar-control: two Redis-backed stores, a versioned snapshot of the fleet's active state delivered on connect plus a REST mirror for fallback polling, and a WebUI that resets to the snapshot and applies deltas on top.

## Goal

- **solar-control — instance state store:** persist the latest runtime state per host:instance at the relay choke points (app/socketio_app/host_handlers.py host_instance_state / host_instance_state_batch, ~lines 339-434) into a new Redis store (module under app/redis_state/, e.g. instance_states.py) with a TTL so entries expire when a host stops reporting. Shape: {host_id, host_name, instance_id, timestamp, data} (the existing InstanceStatePayload, app/models/socketio.py:195).
- **solar-control — active request store:** add a Redis-backed per-request registry written at the single broadcast choke point app/gateway.py::_broadcast_routing_event (~1078-1106): request_start creates, request_routed updates (host/instance/resolved_model), request_success/request_error delete; TTL mirroring ACTIVE_TTL_S (app/redis_state/routing.py, 300 s). This makes active requests fleet-wide and replica-consistent, replacing reliance on the per-pod GatewayLogger._inflight (app/database/logs.py:123-139).
- **solar-control — snapshot builder:** new service (e.g. app/services/render_state.py) composing a typed, versioned payload (schema_version, generated_at) from: hosts (status + drain + health), instances per host, instance states, active requests (with the tallies currently computed in apps/solar-webui/src/components/routing/workload.ts: inFlight per instance/host/model/endpoint, queued/processing/errored totals), endpoints, pending hosts.
- **solar-control — connect snapshot:** in app/socketio_app/webui_handlers.py::webui_connect (~44-75), after initial_status, emit a routing_snapshot event to the sid before any deltas flow.
- **solar-control — REST mirror:** new GET /api/routing/state under app/routes/management/routing.py (registered in app/routes/management/__init__.py, /api prefix) returning the same snapshot payload, same auth as the other management routes.
- **solar-webui — snapshot consumer:** in apps/solar-webui/src/hooks/useEventStream.ts, on socket connect reset the event-derived Maps (requests, instanceStates, endpoints), gate handleEvent deltas until the snapshot event is applied, then apply it wholesale and resume processing. Reuse the existing bindEvent pattern.
- **solar-webui — REST fallback:** switch useFallbackPolling consumers (e.g. RoutingFlow.tsx endpoints fetch, ~88-107) to poll the snapshot endpoint when the socket is down, same payload shape as the WS event.
- **solar-webui — ticker backfill:** after applying a snapshot, backfill recent terminal events for the ticker via the existing GET /api/gateway/events/recent; live active requests come from the snapshot.
- **solar-webui — derive from snapshot:** routing/workload.ts and routing/graph.ts consume the snapshot's aggregates (inFlight, totals) instead of re-deriving from the client request Map; search/expand/trace/layout logic stays client-side.
- **Tests:** control unit tests for both stores (TTL expiry, cross-pod delete semantics) and the snapshot builder; webui vitest for reset-on-connect, delta gating, and fallback polling switching. The stores follow the existing redis_state test pattern (patch the store's own namespace).
- **Out of scope:** view-state features (graph layout, search, expand/collapse, traces, minimap), gateway history UI, and the Data Repository.
