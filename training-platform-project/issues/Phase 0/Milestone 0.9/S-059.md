# S-059: Cursor proxy endpoint (/cursor/v1) for DeepSeek reasoning-effort control

## Description

Cursor cannot control reasoning effort on custom-endpoint models and drops
`reasoning_content` from multi-round tool-call history, which breaks
DeepSeek thinking-mode agent loops and hides thinking traces from the UI.
Team members currently run yxlao/deepseek-cursor-proxy locally with ngrok
tunnels as a workaround — one tunnel per user, leaking the model through a
public endpoint.

This issue integrates the proxy's logic into solar-control as a native
endpoint, `/cursor/v1`, backed by the already-deployed
`deepseek-v4-flash:284b` instance on the solar gateway. The proxy exposes
model aliases that bake the reasoning effort into the model name, because
Cursor offers no effort control for custom models:

| Cursor-facing alias | Upstream model | reasoning_effort |
|---|---|---|
| `deepseek-v4-flash:max` | `deepseek-v4-flash:284b` | `max` |
| `deepseek-v4-flash:high` | `deepseek-v4-flash:284b` | `high` |
| `krumpli:max` | `deepseek-v4-flash:284b` | `max` |
| `krumpli:high` | `deepseek-v4-flash:284b` | `high` |

The `krumpli:*` pair exists because Cursor hardcodes a 200K context window
for recognized DeepSeek model names but falls back to its 1M default for
unrecognized names. Both pairs are advertised side by side so users can
pick whichever Cursor treats correctly.

## Design

- **Port, don't wrap.** The proxy's transform/streaming/reasoning modules
  (MIT, yxlao/deepseek-cursor-proxy) are ported into
  `apps/solar-control/app/cursor_proxy/`. The http.server handler becomes
  FastAPI routes in `app/routes/cursor.py` with prefix `/cursor/v1`
  (surface: `/models`, `/chat/completions`).
- **Single-key trust model.** The proxy holds no credentials of its own.
  The caller's API key authenticates the `/cursor/v1` hop through the
  existing auth middleware (api_keys table), and the SAME Authorization
  header is forwarded verbatim on a self-HTTP call to solar-control's own
  `/v1` gateway (`http://127.0.0.1:<port>/v1`). Solar Control resolves the
  key a second time, so gateway telemetry attributes every request to the
  caller's endpoint. The management key is explicitly REJECTED on
  `/cursor/v1` — only tenant endpoint keys are accepted.
- **Reasoning cache in Redis, not SQLite.** solar-control is stateless and
  runs multiple replicas; a per-pod file cache would miss on the replica
  that did not see the previous turn. The conversation-scope key math is
  ported verbatim; the store backend becomes shared Redis (TTL + max-rows
  cap via a sorted set).
- **Multi-replica safe by construction**: all shared state (cache,
  endpoint resolution, registry metadata) lives in Redis; the self-HTTP
  call targets the pod's own gateway, so no cross-pod dependence exists.
- **Effort wiring.** `prepare_upstream_request` gains a
  `reasoning_effort` override; the router resolves the alias and injects
  the effort. Upstream verification (2026-08-19 spike against the live
  gateway) confirmed SGLang honors `reasoning_effort` (`max` vs `high`
  produce measurably different reasoning), accepts the `thinking` field,
  streams `reasoning_content` through, and does NOT 400 on missing
  reasoning (so the repair store is a quality feature here, not a
  correctness gate).

## Goal

Cursor users can set base URL `https://solar-api.damit.cloud/cursor/v1`,
pick one of the four aliases, and chat/agent with DeepSeek V4 Flash with
visible thinking blocks, working multi-round tool calls, and explicit
effort control — attributed to their own endpoint key in gateway stats.

## Acceptance criteria

- [ ] `/cursor/v1/models` advertises exactly the four aliases with 1M context
- [ ] `/cursor/v1/chat/completions` streams and non-streams with
      `reasoning_content` mirrored into collapsible thinking blocks
- [ ] Multi-round tool-call requests without `reasoning_content` get the
      chain-of-thought restored from the Redis cache
- [ ] `:max` and `:high` aliases send different `reasoning_effort` upstream
- [ ] Endpoint keys authenticate; the management key returns 401
- [ ] Endpoint model scoping gates the upstream hop (model_not_found when
      the endpoint cannot serve `deepseek-v4-flash:284b`)
- [ ] Works with multiple replicas (shared cache) without configuration
- [ ] solar-control unit suite green; lint clean
