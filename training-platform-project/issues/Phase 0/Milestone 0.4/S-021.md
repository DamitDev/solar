# S-021: Design shared workspace volume layout for job step execution

## Description

Solar Host needs a documented ephemeral workspace layout for running step-based training jobs. Each step container is an opaque image that reads and writes files through mounted directories; the platform must not depend on container internals beyond the agreed workspace contract.

This workspace is per-job and separate from the managed inference `MODELS_DIR` cache used by Solar model distribution.

## Goal

- Document the job workspace layout, including `/workspace/models/`, `/workspace/data/`, `/workspace/output/`, `/workspace/config/`, and any host-side root path convention.
- Define lifecycle rules: create workspace before the first step, mount the same workspace into every step, preserve artifacts until job completion, and clean up according to retention policy.
- Specify expected ownership, permissions, disk-space checks, and safe path handling so step inputs cannot escape the job workspace.
- Clarify that step containers are opaque and communicate only through mounted files, environment variables, exit codes, and logs.
- Include examples for model download, dataset download, training, conversion, and upload steps.
