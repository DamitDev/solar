# S-030: Build `supernova-step-upload-model` image

## Description

After training or conversion, SuperNova pipelines need a step image that uploads model artifacts from the ephemeral job workspace to Harbor and registers the resulting version with the Data Repository. Harbor stores the blobs; Data Repository stores metadata and verifies the pushed artifact.

The image should push directly to Harbor using `harbor-oci-client` / ORAS, then call Data Repository registration APIs. It must not rely on Solar Control for blob transfer.

## Goal

- Build a Docker image named `supernova-step-upload-model` in the `supernova-steps` repo.
- Accept source path, artifact/model name, optional version, Harbor target, and metadata path or JSON arguments.
- Push the source directory or file set from `/workspace` to Harbor with `harbor-oci-client` / ORAS.
- Call Data Repository model registration with `harbor_ref`, version, checksum/size where available, and metadata.
- Fail clearly for missing source files, path escape attempts, Harbor auth/push errors, and Data Repository registration errors.
- Provide a minimal README or usage example and a local smoke test command.

### S-021 Workspace Reference

The `/mnt/nvme/AI/damit-aiops/solar/training-platform-project/docs/specs/job-step-workspace.md` defines the full contract. Key points for this step:

- **Environment input:** `MODEL_SOURCE_PATH`, `HARBOR_TARGET_REF`, `ARTIFACT_NAME`, `VERSION`, `ARTIFACT_CATEGORY`, `METADATA_PATH` (Section 4.3), plus all workspace paths and infrastructure credentials (Sections 4.1–4.2).
- **Reading previous step results:** Read `job.json` → `steps.train.best_checkpoint_path` (or `steps.convert_model.*`) to determine what to upload. The train step writes this; the upload step consumes it. This is the inter-step communication chain.
- **Metadata aggregation:** Combine `upload-metadata.json` from `/workspace/config/` (produced by the train step) with information from `job.json` when constructing the Data Repository registration payload. The metadata JSON follows the conventions in Data Repository's `/mnt/nvme/AI/damit-aiops/solar/apps/data-repository/docs/schema.md` (`training_config`, `model_config`, `eval_metrics`, `lineage`).
- **Push:** Use `harbor-oci-client` / ORAS to push from `MODEL_SOURCE_PATH` to Harbor at `HARBOR_TARGET_REF`.
- **Register:** `POST /api/models/{ARTIFACT_NAME}/versions` to Data Repository with the Harbor ref, digest, size, and metadata.
- **Write to config:** Update `job.json` → `steps.upload_model` with the Harbor reference and registration result.
- **Path safety:** Validate that `MODEL_SOURCE_PATH` is under `/workspace/output/`.
