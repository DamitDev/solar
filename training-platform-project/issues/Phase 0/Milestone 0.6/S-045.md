# S-045: Fix the upload_model artifact layout to flat file-per-layer

## Description

The `upload_model` step pushes trained models to Harbor via `OrasHelper.push_custom`, which tars the content directory into a single `model.tar.gz` layer with the SuperNova weights media type. Solar Host pulls artifacts flat (`OrasHelper.pull`) and never untars them, so a pulled artifact contains one file called `model.tar.gz`. `_select_gguf_path` then finds no `.gguf` and `pull_model` fails with `404 not_found` — "an artifact without any .gguf is a client error".

The result is that no model produced by a SuperNova training pipeline can be deployed on llama.cpp. This was verified against the live registry: a `push_custom` artifact pulls back as `['model.tar.gz']` with GGUF selection returning `None`, while the same fixture pushed flat pulls back as `['config.json', 'model-Q4_K_M.gguf', 'tokenizer.json']` and selects the `.gguf` correctly.

Flat file-per-layer is also what Solar Host's post-pull integrity check already assumes — its docstring reads "flat layers: layer digest = sha256 of the exact file bytes" — and it is what makes `repo://name:version/subpath` addressing work. The tarball defeats both.

## Goal

- Replace the `push_custom` call in `push_to_harbor` with a flat push: one OCI layer per file, layer digest = sha256 of the raw file bytes, file name carried in the `org.opencontainers.image.title` annotation. `OrasHelper.push` already does this; only the SuperNova-typed config blob needs custom assembly.
- Walk the source directory recursively and use the path relative to the artifact root, POSIX-separated, as the layer title.
- Validate titles before pushing: relative only, no `..` segments, no leading `/`, no duplicates. Raise `PushError` otherwise.
- Remove `prepare_content_dir`. A single-file source becomes a one-layer artifact titled after the file, with no temporary directory and no copy.
- Skip symlinks instead of following them, matching the behaviour of `compute_dir_size`.
- Pass `size_bytes` to `register_version` (the sum of file sizes) and update the docstring that explains why it was previously omitted — stored bytes now equal source bytes, so the value is truthful.
- Rewrite the existing `push_custom` unit tests for the flat layout and add cases for path traversal, duplicate titles, symlinks, single-file sources, and the config media type.
- Run `make test-supernova-steps` and `make lint-supernova-steps`.
