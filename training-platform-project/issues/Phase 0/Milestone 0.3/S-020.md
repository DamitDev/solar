# S-020: Implement model availability query in solar-control

## Description

Solar Control has no aggregated view of which models exist on which hosts. The gateway and instance creation flow operate per-host. Resource coordination and instance migration need to know "which hosts have model X" to avoid unnecessary distribution or to select a host that already has the model.

S-014 provides `GET /models` on each solar-host. This issue aggregates that data across all hosts.

## Goal

- Implement `GET /api/models/availability` in solar-control. Query parameter (optional): `model_name` to filter for a specific model.
- Flow: (1) Get all hosts from DB (or only connected hosts via Redis). (2) For each host, call `GET {host.url}/models` with host's API key. (3) Aggregate results: for each model name, list host_ids (or host names) that have it.
- Response shape: `{"models": {"model-a": ["host-id-1", "host-id-2"], "model-b": ["host-id-1"]}}` or `{"model-a": [{"host_id": "...", "host_name": "...", "size_bytes": ...}], ...}`.
- Handle unreachable hosts: omit them from results or include with `status: "unreachable"`. Do not fail the entire request.
- Require management API key.
- Support optional `?model_name=xyz` to return only hosts that have that model.

## Additional Notes

- Repo: `solar-control` at `/mnt/nvme/AI/solar/solar-control`
- Key files: new `app/routes/management/models.py` or extend existing, `app/database/hosts.py`
- Depends on S-014 (GET /models on solar-host).
- Used by instance migration (S-037), resolver cache checks, and operational dashboards.
