# S-015: Implement `POST /models/pull` on solar-host

## Description

Solar Host has no API to acquire models programmatically. Models are expected to exist on disk before instance creation. The model source abstraction requires Solar Host to pull models directly from their sources (Harbor via ORAS, HuggingFace Hub) when instructed by Solar Control.

Following the Kubernetes model (hosts pull directly from registries, control plane orchestrates), Solar Host handles the actual download. Solar Control resolves URIs to pull instructions (e.g. harbor_ref for `repo://`, model_id for `huggingface://`) and sends a pull command. Solar Host checks its manifest cache, downloads if needed, and returns the resolved local path.

S-009 provides the managed models directory and manifest. This issue adds the pull endpoint and download logic.

## Goal

- Implement `POST /models/pull` on solar-host. Request body per spec Section 3.6:
  - For Harbor: `{source: "harbor", harbor_ref: "imgrepo.damit.hu/supernova/iris-osl:v3", source_uri: "repo://iris-osl:v3", digest: "sha256:..."}`
  - For HuggingFace: `{source: "huggingface", model_id: "microsoft/phi-3", source_uri: "huggingface://microsoft/phi-3"}`
- Response: `{path: "/opt/solar/models/repo--iris-osl--v3", cached: true/false, source_uri: "repo://iris-osl:v3"}`
- Cache check: look up `source_uri` in manifest. If found, return cached path immediately (`cached: true`).
- On cache miss:
  - Derive slug from `source_uri` (per spec Section 4.2).
  - For Harbor: use `OrasHelper.pull(harbor_ref, MODELS_DIR/{slug}/)` from `harbor-oci-client`.
  - For HuggingFace: use `huggingface_hub` library to download to `MODELS_DIR/{slug}/`.
  - Update manifest atomically after successful download (write to temp, rename).
- Add `harbor-oci-client` and `huggingface_hub` as dependencies of solar-host.
- Add Harbor credentials to Settings: `HARBOR_URL`, `HARBOR_USERNAME`, `HARBOR_PASSWORD` (env vars).
- Add HuggingFace credentials to Settings: `HF_TOKEN` (env var, optional for public models).
- Handle errors per spec Section 6: source unreachable (502), auth failed (401), not found (404), disk full (507), missing credentials (500). Return structured JSON errors.
- Require API key authentication.
