# S-018: Add free space validation before model operations

## Description

Solar Host's model pull (S-015) can fail or cause disk-full conditions if the target has insufficient space. S-003 adds disk space reporting to `/health` (total, used, available for models directory). This issue adds proactive validation before pulls to avoid partial downloads and wasted bandwidth.

Validation should happen before the download begins.

## Goal

- Before `POST /models/pull` begins downloading: if the expected model size is known (e.g. `size_bytes` from Data Repository metadata, passed in the pull request), compare with available disk space for `MODELS_DIR`. If `available < required`, return 507 Insufficient Storage with message: "Insufficient disk space. Available: X GB, required: Y GB."
- For pulls without known size (e.g. HuggingFace models where size is not known upfront): monitor disk usage during download and abort if available space drops below a configurable threshold.
- Before model distribution (S-019): solar-control can optionally query target host's disk availability (from `/health`) before issuing the pull command. This may be implemented in S-019; document the contract here.
- Integrate with S-003: use the same disk usage logic (e.g. `psutil.disk_usage(MODELS_DIR)`). Ensure `/health` disk fields are available for solar-control to query.

## Additional Notes

- Repo: `solar-host` at `/mnt/nvme/AI/damit-aiops/solar/apps/solar-host`
- Key files: `app/routes/models.py` (pull handler), `app/main.py` (health endpoint if disk not yet added)
- Depends on S-003 (disk reporting), S-015 (pull endpoint to add validation to).
- S-019 (model distribution) can optionally check target host disk before pull; that logic can live in solar-control.
