# S-019: Implement model distribution in solar-control

## Description

Solar Control proxies instance creation to individual hosts. There is no capability to ensure a model is available on a specific host. Instance migration (S-037) and resource coordination require models to be available on the target host; today that would require manual copying.

With the updated model source architecture (see `docs/specs/model-source-uri.md`), model distribution is source-based: Solar Control tells the target host to pull the model from its authoritative source (Harbor or HuggingFace Hub). This avoids host-to-host byte transfer and leverages the same `POST /models/pull` mechanism used for initial model acquisition.

## Goal

- Implement `POST /api/models/distribute` in solar-control. Request body: `target_host_id`, `source_uri` (model source URI, e.g. `repo://iris-osl:v3` or `huggingface://microsoft/phi-3`). Optional: `source_uri` could be a list for batch distribution.
- Flow: (1) Resolve target host from DB. (2) Parse `source_uri` and resolve metadata if needed (e.g. query Data Repository for `harbor_ref` on `repo://` URIs). (3) Call `POST {target_host.url}/models/pull` with the pull instructions. Solar Host checks its cache and downloads if needed. (4) Return 200 with summary: source_uri, target host, path, cached (true/false).
- Optionally validate target host has sufficient disk space before starting (query target's `/health` for disk.available).
- Handle errors: host unreachable, pull failures (404, 502, 507, auth). Return appropriate HTTP status and message.
- Require management API key. Route under `/api/models/` (create new router or add to management routes).
