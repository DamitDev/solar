# S-017: Implement `DELETE /models/{name}` on solar-host

## Description

Solar Host has no API to remove models. Once a model is uploaded or downloaded, it remains until manually deleted. Operators need to free disk space or remove obsolete models. Deleting a model that is in use by a running instance would cause failures; the endpoint must reject such requests.

S-014 provides `GET /models` to list models. This issue adds deletion with in-use validation.

## Goal

- Implement `DELETE /models/{name}` on solar-host. Path parameter `name` identifies the model.
- Before deletion: check if the model is in use by any running instance. Compare the model path (from manifest) with `config.model` (llama.cpp) or `config.model_id` (HuggingFace, if it's a path) for all instances in `config_manager.get_all_instances()`. If any instance uses this model (path matches or is under the model directory), return 409 Conflict with message: "Model is in use by instance {id}. Stop the instance first."
- If not in use: remove the model directory (or file) from disk, remove entry from manifest, return 200.
- Return 404 if model not found.
- Require API key authentication.

## Additional Notes

- Repo: `solar-host` at `/mnt/nvme/AI/damit-aiops/solar/apps/solar-host`
- Key files: `app/routes/models.py`, `app/config.py` (config_manager for instance list)
- Depends on S-014 (model list structure; in-use check uses instance configs from config_manager).
- Path matching: for HuggingFace models, `model_id` can be a Hub ID (no path) or a local path. Only local paths need to be checked against the model directory.
