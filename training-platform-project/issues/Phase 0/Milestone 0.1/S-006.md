# S-006: Add role-based host filtering to `GET /api/hosts` and resource availability to host status responses

## Description

Solar Control's `GET /api/hosts` returns all hosts with no filtering. The route (`app/routes/management/hosts.py`) calls `host_db.get_all_hosts()` and returns the list. Host status responses (from DB and Socket.IO) include `memory` but not structured resource availability (disk, available VRAM).

SuperNova needs to query hosts by role (e.g. "give me training-capable hosts") and to see resource availability when selecting a host for a job.

## Goal

- Add optional query parameter `role` to `GET /api/hosts` (e.g. `?role=training`). Filter hosts where `roles` array contains the requested role. If `role` is omitted, return all hosts (backward compatible).
- Include resource availability in host responses: `disk` (total/used/available), `memory` (existing), `memory_available` or `available_gb` if available. Ensure `GET /api/hosts` and `GET /api/hosts/{id}` return these fields when present.
- Update Socket.IO `host_status` and `host_health` events to include resource availability so the WebUI receives real-time updates.

## Additional Notes

- Repo: `solar-control` at `/mnt/nvme/AI/damit-aiops/solar/apps/solar-control`
- Key files: `app/routes/management/hosts.py`, `app/database/hosts.py` (add `get_hosts_by_role` or extend `get_all_hosts` with filter), `app/socketio_app/host_handlers.py`
- Depends on S-005 (host data model stores roles and resource fields).
