# S-003: Add disk space reporting to `/health` endpoint

## Description

Solar Host's `/health` endpoint (`app/main.py`) returns only `{"status": "healthy", "service": "solar-host", "version": "2.0.0"}`. There is no disk usage information. The models directory path is not yet formalized (Milestone 0.2 introduces `MODELS_DIR`).

SuperNova needs disk availability to decide where to place models and training artifacts. Model uploads and downloads must validate available space before proceeding.

## Goal

- Add disk space reporting to the `/health` endpoint response.
- Report total, used, and available disk (in GB or bytes) for the models directory. Use `MODELS_DIR` env var if available; otherwise a sensible default (e.g. `./models` or current working directory).
- Use `psutil.disk_usage(path)` or equivalent to compute values.
- Response shape example: `{"status": "healthy", "service": "solar-host", "version": "2.0.0", "disk": {"total_gb": 500, "used_gb": 120, "available_gb": 380}}`

## Additional Notes

- Repo: `solar-host` at `/mnt/nvme/AI/damit-aiops/solar/apps/solar-host`
- Key files: `app/main.py` (`health_check`), `app/config.py` (add `models_dir` / `MODELS_DIR` if not yet present)
- S-009 will introduce managed models directory; this issue can use a preliminary path.
