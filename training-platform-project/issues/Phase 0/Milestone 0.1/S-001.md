# S-001: Add `roles` field to solar-host config

## Description

Solar Host currently has no concept of host roles. The `config.json` stores only instance configurations, and host-level settings (API key, solar-control URL, host name) come from `.env`. Solar Control and the WebUI treat all hosts uniformly for inference routing.

SuperNova requires hosts to declare their capabilities—e.g. whether they can run inference, training, or both. This enables the orchestrator to route training jobs to training-capable hosts and inference to inference-capable hosts.

## Goal

- Add a configurable `roles` field to solar-host configuration. Suggested location: top-level in `config.json` (e.g. `{"roles": ["inference", "training"], "instances": [...]}`) or as an env var `HOST_ROLES` (comma-separated).
- Default to `["inference"]` for backward compatibility.
- Include `roles` in the registration event payload sent to solar-control via Socket.IO (`_send_registration` in `app/ws_client.py`). The registration event currently sends `host_name` and `instances`; extend it to include `roles`.

## Additional Notes

- Repo: `solar-host` at `/mnt/nvme/AI/solar/solar-host`
- Key files: `app/config.py` (ConfigManager, config.json schema), `app/ws_client.py` (`_send_registration`, `SolarControlClient`)
