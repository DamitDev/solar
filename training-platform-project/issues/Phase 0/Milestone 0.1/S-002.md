# S-002: Add GPU type detection to host registration

## Description

Solar Host's `memory_monitor.py` detects VRAM (NVIDIA via pynvml) or RAM (macOS via psutil) and reports `memory_type` as "VRAM" or "RAM". There is no explicit GPU type classification. Solar Control and the WebUI do not know whether a host has NVIDIA CUDA, Apple MPS, or CPU-only acceleration.

SuperNova needs to know the acceleration backend to select compatible training images and allocate resources correctly (e.g. NVIDIA Container Toolkit vs CPU-only containers).

## Goal

- Add GPU type detection based on available hardware. Report one of: `nvidia_cuda`, `apple_mps`, `cpu`.
- Include `gpu_type` in the registration event payload sent to solar-control.
- Detection logic: if pynvml reports NVIDIA GPUs → `nvidia_cuda`; if macOS with M-series (or MPS available) → `apple_mps`; otherwise → `cpu`.

## Additional Notes

- Repo: `solar-host` at `/mnt/nvme/AI/solar/solar-host`
- Key files: `app/memory_monitor.py` (platform detection), `app/ws_client.py` (registration payload)
- Consider adding `gpu_type` to `host_health` events as well for consistency.
