# S-036: Add instance priority levels

## Description

Solar needs a policy signal for deciding which inference instances can be moved or stopped when resources are needed for training jobs, migrations, or deployment updates. Today instances have no explicit priority, so coordination logic would need to infer importance from ad hoc metadata.

This issue adds a consistent `priority` field for inference instances. The supported values are `production`, `staging`, and `ephemeral`. Solar Control uses this field for placement and eviction decisions; Solar Host persists and reports it as part of local instance configuration/status.

## Goal

- Add `priority` to instance create/update payloads and stored instance state.
- Support exactly `production`, `staging`, and `ephemeral` as the initial priority levels.
- Define a default priority for existing/manual instance creation flows, preferably `production` unless the current API has a safer established default.
- Include `priority` in Solar Control instance responses, host status aggregation, and any host-local instance status payloads.
- Ensure lower-priority instances can be selected for migration or stop before higher-priority instances when Solar Control frees resources.
- Preserve the one-replica-per-host rule for the same deployed model/alias regardless of priority.
- Validate invalid priority values with clear API errors.
