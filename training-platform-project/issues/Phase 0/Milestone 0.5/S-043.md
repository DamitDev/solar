# S-043: Implement host draining in solar-control

## Description

Taking a host out of service for maintenance (OS upgrade, GPU driver swap, physical move) has no supported path today. An operator can delete the host record (`DELETE /api/hosts/{id}`), but that only removes the database row and leaves the running instances orphaned on a machine Solar Control no longer knows about. The alternative is stopping each instance by hand, which for intent-managed replicas is futile: the S-041 reconciler observes the shortfall and recreates them on the same host within a tick.

The building blocks exist. S-037 provides `execute_migration()` for moving one instance to another host, S-038/S-041 share one placement policy in `placement.find_candidates()`, and the reconciler already converges managed instances toward the intent. What is missing is a host-level desired state that says "no new work here, and move the existing work away", plus the reconciler rule that acts on it.

`placement.host_deny` on an intent is not a substitute: it excludes a host from *new* placement for that one intent and never moves anything that is already running.

Draining is deliberately declarative rather than a long-running orchestrated job. The state lives on the host row, so it survives a Solar Control restart mid-drain and is visible to every replica; evacuation is then just another reconciler action, which inherits the existing per-intent Redis lock and needs no new cross-replica coordination.

## Goal

- Add a durable drain state to the host record, independent of the existing `status` (`online`/`offline`/`error`) — reachability and drain intent are orthogonal, and a host being drained is still online. States: not draining, `draining` (evacuating), `drained` (evacuation complete). Include the timestamp the drain was requested.
- Add an Alembic migration for the new columns, following the existing guarded `information_schema` pattern so re-running against a live database is safe.
- Expose three endpoints on solar-control:
  - start a drain — runs a preflight, then marks the host `draining` and wakes the reconciler,
  - cancel a drain / resume the host — clears the state and wakes the reconciler,
  - read drain progress — remaining managed replicas, anything blocking the drain, and a per-replica reason when a replica cannot be moved.
- Preflight rules, rejected with a structured `409` that lists the blockers so the WebUI can render them:
  - **Manually created instances are never evacuated.** They have no desired state to reconcile against, so moving them would be an unrequested decision about someone else's workload. If any manual instance is still running, refuse to start the drain and name them; the operator stops them first. Manual means the instance lacks the `managed_by`/`intent_id` ownership markers the reconciler uses.
  - Refuse while the host has non-terminal job steps. Migration already rejects a source host with active training jobs, so a drain started in that state would stall on every replica with no useful signal.
- Exclude draining and drained hosts from `placement.find_candidates()` so no new work lands on a host being emptied. Doing it in the shared placement helper covers the reconciler and the S-038 reservation coordinator with one policy, and prevents a drain from pushing replicas onto another draining host.
- Add an evacuation action to the reconciler: a managed instance on a `draining` host is migrated to the best remaining candidate through the S-037 migration path, one action per tick like every other reconciler action. This is distinct from the existing displacement migration, which moves *other* instances off a target host to make room.
- **A drain must never reduce serving capacity on its own.** If no candidate host can accept a replica, leave it running, keep the host `draining`, and report the reason. Do not stop the replica to make the drain finish, and do not let a stalled drain look identical to a progressing one.
- Promote `draining` to `drained` once the host has no instances left, and broadcast the change so the WebUI reflects it without polling. Add the drain state to the aggregated resource view and the host status Socket.IO payload, since those are what operator views read.
- Resuming a host clears the state from either `draining` or `drained` and lets placement consider it again. Replicas that were moved away are not moved back — the reconciler treats the current placement as satisfying the intent.
- Cover with unit tests: preflight rejection on manual instances and active jobs, placement skipping drained hosts, the reconciler emitting an evacuation for a managed instance on a draining host, the stall path when no candidate exists, and the promotion to `drained`.

## Additional Notes

- Repo: `solar-control` at `/mnt/nvme/AI/damit-aiops/solar/apps/solar-control`
- Specification: `docs/specs/host-draining.md` defines the states, preflight rules, endpoint contracts and stall semantics. `docs/specs/deployment-intent.md` §8.4 (placement policy) and §8 (reconciler actions) carry the matching updates.
- Key files: `app/database/tables.py` and `app/database/migrations/versions/` (host columns), `app/database/hosts.py`, `app/models/host.py` (`Host`, `HostStatus`, `HostResourceSnapshot`, `HostInstanceSummary`), `app/routes/management/hosts.py`, `app/routes/management/resources.py`, `app/services/placement.py`, `app/services/reconciliation.py`, `app/services/migration.py` (`execute_migration`, `check_no_active_training`), `app/models/socketio.py`.
- Depends on S-037 (instance migration), S-041 (reconciliation engine), and the shared placement helper from S-038.
- Downstream consumer: U-005 (drain controls in Solar WebUI).
- The instance ownership test must match the reconciler's existing one (`managed_by == "intent"` and `intent_id` equal to the intent) so the same instance is never classified differently by the drain preflight and the reconciler.
- Draining is orthogonal to the `roles` field. Removing the `inference` role from a host would also stop new placement, but it is a capability statement, not a lifecycle state, and it does not evacuate anything.
