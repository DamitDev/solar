# S-051: Model pull progress telemetry and progress-aware cold-start bounds

## Description

A multi-GB model pull takes minutes, but the reconciler bounded every
cold-start action at a raw 60 seconds: `asyncio.wait_for(self._act(...),
timeout=_ACTION_TIMEOUT_S)` ran on the normal reconcile path for CREATE as
well as for quick actions. Long pulls were killed mid-flight with a bare
`TimeoutError` ("start failed"), the pull was retried, and the user saw no
progress anywhere.

## Goal

- `pull_model` on the host accepts a `progress_cb`; the parent poll loop
  emits throttled `downloading` events with `bytes_done`, `bytes_total` and
  `speed_bps`, plus `resolving`/`verifying`/`finalizing` and exactly one
  terminal `completed` or `failed` event.
- Hosts push `pull_progress` over the WS channel; control caches the latest
  per `{host_id}|{source_uri}` in Redis (`solar:hosts:pulls`) and
  rebroadcasts to `/webui`; `GET /api/pulls` serves the cache.
- The reconciler's normal path waits with `_await_action_with_progress`:
  cold-start actions are bounded by `_action_timeout_s(action)` (the
  settings-derived cold-start bound), the wait is sliced, and fresh pull
  progress extends the wait up to the bound. A give-up while the host is
  still working records `recoverable: true` on the last_error.
