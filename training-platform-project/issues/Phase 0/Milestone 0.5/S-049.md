# S-049: Drift-safe backend comparison and the churn circuit breaker

## Description

An intent edit with a backend whose values the host re-normalizes (e.g.
`chat_template_kwargs` written compact by the host's own coercion) trapped
the intent in a stop/recreate loop: every reconcile tick detected drift,
planned a REPLACE, and the replacement reproduced the same "drift" the next
tick. The observable symptoms were instance ids churning on every host,
`spec_changed_at` never clearing, and repeated `/stop` traffic towards the
hosts. `_detect_backend_drift` compared backend values with plain Python
`==`, which is not the same comparison the host's config coercion performs.

## Goal

- Compare backend values with JSON-structural semantics: parse JSON strings
  on both sides, recursively compare with boolean coercion mirroring
  `solar_host.models.llamacpp._coerce_template_kwargs`, and resolve glob /
  relative-path values before comparing.
- Canonicalize `chat_template_kwargs` at the control API boundary
  (`canonicalize_intent_backend`) so persisted intents start out in the same
  compact form the host produces.
- Add a churn circuit breaker: consecutive drift-driven REPLACE rounds are
  bounded by `settings.max_drift_replace_attempts`; past the limit the
  intent records a `BackendDriftUnsettled` last_error naming the drifted
  keys (condition `Degraded/DriftUnsettled`) instead of planning more
  REPLACEs. The counter resets when the spec settles or the user edits.
- Surface `status.drift_replace_attempts` in the API.

## Additional Notes

Unit coverage: `tests/test_drift_circuit_breaker.py` (6 tests) and the
canonicalization matcher tests in `tests/test_reconciliation.py`; the
