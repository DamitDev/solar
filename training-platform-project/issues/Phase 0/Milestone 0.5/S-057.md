# S-057: Zero-downtime evacuation for host draining (create-then-stop)

## Description

S-043 promised that "a drain never reduces serving capacity on its own"
(`docs/specs/host-draining.md` §1) and that evacuation "preserves the
replica; the alias keeps serving from the target" (§4.2). The
implementation does not deliver that. The reconciler's EVACUATE action
(`app/services/reconciliation.py:1934`) calls `execute_migration`
(`app/services/migration.py:650`), whose documented ordering is
stop-before-create: *"For rolling / zero-downtime migrations, the S-042
strategy layer will orchestrate create-then-stop on top of this
primitive."* No such orchestration exists for evacuation.

Actual sequence during a drain: the model is pulled on the target first
(the long step, and the source keeps serving through it — good), then the
source is stopped (`migration.py:798`), disowned, and a target instance is
created — but the host creates instances in `STOPPED` state
(`solar_host/process_manager.py:925`), and the target only starts serving
after the next reconciler tick RECREATEs it (`reconciliation.py:1887`,
`_start_instance` blocks on log-gated readiness). The alias is dark from
the source stop until the target's cold start completes — seconds to
minutes depending on model load.

The integration test does not catch this: `test_host_drain.py` asserts
final convergence ("the intent is ready again on the target"), never
continuity of the alias during the drain.

## Goal

- Add `execute_evacuation()` to `app/services/migration.py`, mirroring
  `execute_migration`'s validation, capture and model distribution but
  with create-then-stop ordering: ensure model on target → create target
  (stopped, with intent markers) → **start target and block on log-gated
  readiness** → stop source → disown source → delete source. Reuse the
  shared helpers (`create_instance_on_host`, `stop_source_instance`,
  `disown_source_instance`, `ensure_model_on_target`, `_build_result`).
- Switch the reconciler's EVACUATE executor (`reconciliation.py:1934`) to
  `execute_evacuation`. `execute_migration` stays untouched: the manual
  API migration path keeps its documented stop-before-create semantics
  (D-017: the operator may want to inspect the stopped source).
- Keep the drain contract: no eligible target → replica keeps serving and
  a stall is recorded (unchanged). Target create/start failure → delete
  the target replica, record a stall, source keeps serving. Align failure
  handling with spec §4.3 (a stalled drain re-evaluates every tick, no
  backoff).
- Race protection: refresh the per-intent settle window after the target
  is created and again after it is running (before the source stop), so a
  mid-overlap tick cannot act on the brief two-replica state. The surplus
  logic already prefers replicas on draining hosts
  (`reconciliation.py:1577-1582`), so a missed window degrades to
  stopping the source — never the fresh target.
- Amend `docs/specs/host-draining.md` §4.2: the current text describes
  evacuation as "migrate via S-037", which is the mechanism that caused
  this bug. Describe the create-then-stop mechanism.
- Tests: unit tests for `execute_evacuation` ordering and failure paths;
  an integration assertion that the alias stays serving throughout a
  drain (continuity, not just final convergence).
