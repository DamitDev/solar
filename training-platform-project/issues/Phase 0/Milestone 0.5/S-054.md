# S-054: Update grandfathering, path-scoped drift comparison, gpu_type read-path normalization

## Description

Three independent correctness gaps left by S-049 and S-052, each in the
validation/reconciliation boundary.

**Update grandfathering.** S-052 tightened field ownership and modality
rules. Two of the three backend validators received an
`ownership_exempt_fields` set so an update carrying a stored value over
unchanged is not re-judged; `_validate_backend_model_selection` did not.
Its `model_file` and `mmproj` rules therefore fired on untouched stored
values, permanently blocking every edit to a configuration that was legal
before the tightening — the user is asked to fix a field their backend's
form does not even render.

**Path-scoped drift comparison.** The glob/relative-path layer of
`_backend_value_matches` applied to any two strings, not just to fields
the host resolves to a path. `ot` is a regular expression that routinely
contains `*`, `?` and `[`, so a changed routing expression could
`fnmatch` the previous spec value and read as "no drift", keeping a stale
instance alive past a genuine config change. A bare `*` matched
unconditionally.

**gpu_type read path.** `validate_intent_create` normalizes
`placement.gpu_type` to the canonical token on save and the fleet
validator normalizes before filtering, but the reconciler compared the raw
stored value. A legacy intent stored as `mps` was therefore reported as
placeable by validation while the reconciler placed nothing and produced a
shortfall reason blaming the fleet.

## Goal

- Give `_validate_backend_model_selection` an `exempt_fields` parameter and
  skip `model_file` and `mmproj` when the field is carried over unchanged.
  Do **not** exempt `file_filters`: it is validated against `model_source`,
  which an update may change independently. Fold `model_file`'s
  wrong-backend check into the ownership table so a single mechanism
  grandfathers it.
- Scope the path/glob layer of `_backend_value_matches` to the resolved
  path keys (`model_file`, `mmproj`, `chat_template_file`) and require the
  instance value to be absolute, so a relative value cannot tail-match.
- Apply `normalize_gpu_type` at the reconciler's points of use — the
  candidate filter and `_shortfall_reason` — falling back to the raw value
  when normalization returns `None`, matching the fleet validator.
- Update spec §4.7.2 (grandfathering and the `file_filters` exclusion) and
  §8.2.1 (narrowed comparison scope).

## Additional Notes

Unit coverage: update-grandfathering cases in `tests/test_intents.py`,
masked-drift cases in `tests/test_reconciliation.py` (an `ot` regex change
that globs, `mmproj: "*"`, a relative instance value), and paired
validation/reconcile agreement tests in `tests/test_shortfall_reason.py`
and `tests/test_intent_validation_fleet.py`.

A one-shot backfill canonicalizing stored `placement.gpu_type` values is
optional and can ship separately; the read-path normalization makes it
unnecessary for correctness.
