# S-010: Update instance creation on solar-host to accept `model_source` URI alongside existing `model` / `model_id` fields

## Description

Solar Host instance configs use `model` (llama.cpp, path to GGUF) or `model_id` (HuggingFace, Hub ID or path). There is no `model_source` URI. Instance creation (`app/routes/instances.py` → `process_manager.create_instance`) passes config directly to the backend runner, which uses `config.model` or `config.model_id` as-is.

The model source abstraction introduces URIs (`repo://`, `huggingface://`, `local://`). Solar-host must accept `model_source` and resolve `local://` URIs to filesystem paths. `repo://` and `huggingface://` are resolved by solar-control *before* the request reaches solar-host — solar-control calls `POST /models/pull` to ensure the model is in `MODELS_DIR`, then passes a `local://` URI pointing to the downloaded path.

## Goal

- Add optional `model_source` field to instance config schemas. For llama.cpp: accept either `model` (legacy path) or `model_source` (URI). For HuggingFace: accept either `model_id` (legacy) or `model_source` (URI).
- Implement `local://` URI resolution on solar-host. Parse `local://` URIs, validate the path is within `MODELS_DIR` (or allowed base), resolve to absolute path. Use this as the effective `model` / `model_id` for the backend. See spec Section 2.3 for `local://` syntax.
- Resolution order: if `model_source` is present, resolve it; otherwise use `model` / `model_id` as before (backward compatible).
- Reject `repo://` and `huggingface://` at instance creation on solar-host with a clear error: "Model must be resolved via POST /models/pull before instance creation. Use local:// or provide model/model_id path."
- Update `LlamaCppConfig` and HuggingFace configs (`app/models/llamacpp.py`, `app/models/huggingface.py`) to include `model_source: Optional[str] = None`.
- Update `parse_instance_config` and backend runners to use the resolved path when building commands.

## Additional Notes

- Repo: `solar-host` at `/mnt/nvme/AI/solar/solar-host`
- Key files: `app/routes/instances.py`, `app/process_manager.py`, `app/models/llamacpp.py`, `app/models/huggingface.py`, `app/backends/llamacpp.py`, `app/backends/huggingface.py`
- Depends on S-009 (managed models directory, `MODELS_DIR`).
- Solar Control resolves `repo://` and `huggingface://` by calling `POST /models/pull` on solar-host (S-015), then passes a `local://` URI in `model_source` for instance creation.
- Reference: `docs/specs/model-source-uri.md` Sections 2.3 and 7
