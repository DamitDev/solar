# S-009: Implement managed models directory on solar-host

## Description

Solar Host currently has no formal "models directory." Llama.cpp instances use arbitrary filesystem paths (`config.model`), and HuggingFace instances use `model_id` (Hub ID or local path). Models are expected to exist before instance creation; there is no programmatic tracking of what is downloaded or where.

SuperNova and the model source abstraction require a dedicated, env-configurable directory where downloaded models live. Solar Host will pull models directly from sources (Harbor, HuggingFace Hub) to this directory. A manifest file tracks what is present for cache hits and integrity.

## Goal

- Add `MODELS_DIR` to solar-host Settings (`app/config.py`). Default: `./models` or `{config_file_parent}/models`. Env var: `MODELS_DIR`.
- Create the models directory on startup if it does not exist.
- Implement a manifest file (`MODELS_DIR/manifest.json`) that tracks downloaded models. Schema per the URI spec (`docs/specs/model-source-uri.md` Section 5.2):
  ```json
  {
    "models": [
      {
        "slug": "repo--iris-osl--v3",
        "source_uri": "repo://iris-osl:v3",
        "path": "/opt/solar/models/repo--iris-osl--v3",
        "size_bytes": 4815162342,
        "digest": "sha256:abc123...",
        "downloaded_at": "2026-03-31T14:22:00Z"
      }
    ]
  }
  ```
- The manifest is the **single source of truth** for cache detection. Directory existence alone does not count as cached.
- Downloaded models use a flat directory layout with deterministic slugs derived from the source URI (see spec Section 4.2):
  - `repo://{name}:{version}` → `repo--{name}--{version}`
  - `huggingface://{model_id}` → `hf--{model_id}` with `/` replaced by `--`
- Expose the models directory path via a helper (e.g. `get_models_dir()`) for use by instance creation, health/disk reporting (S-003), and future `GET /models` (S-014).
- Implement manifest read/write helpers. Writes must be atomic (write to temp file, rename) to avoid corruption from interrupted writes.
- Implement slug derivation utility function (`source_uri_to_slug(uri)`) for consistent directory naming.
