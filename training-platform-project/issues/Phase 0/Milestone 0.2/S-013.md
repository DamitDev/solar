# S-013: Implement `repo://` resolver stub in solar-control

## Description

The `repo://` URI scheme points to artifacts in the Data Repository (Phase 1). The Data Repository does not exist yet. Solar Control's resolver dispatcher (S-011) must route `repo://` URIs to a resolver; that resolver cannot perform real resolution until Phase 1.

A stub resolver returns a clear, actionable error so that clients and integration tests know the feature is planned but not yet available.

## Goal

- Implement the `repo://` resolver stub in solar-control. Input: URI (e.g. `repo://iris-osl:v3`), target `host_id`.
- Stub behavior: Parse the URI to validate format, then immediately return an error. Error message: e.g. "repo:// resolver not yet available. Data Repository integration will be completed in Phase 1. Use local:// or huggingface:// for now."
- Ensure the stub is registered in the resolver dispatcher (S-011) so that any `repo://` URI is handled (and rejected) rather than falling through to an unhandled path.
- Document the expected behavior once Phase 1 is complete: call Data Repository `GET /api/resolve?uri=...`, obtain `harbor_ref`, pull directly from Harbor (ORAS) to host's managed models directory, return resolved `local://` path.
