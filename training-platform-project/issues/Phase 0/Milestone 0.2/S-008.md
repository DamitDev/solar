# S-008: Design model source URI specification

## Description

Solar currently references models by raw filesystem paths (llama.cpp `model` field) or HuggingFace model IDs (`model_id`). There is no unified URI scheme. SuperNova and Solar need a consistent way to specify model sources: Data Repository artifacts, HuggingFace Hub, or local filesystem. This enables Solar Control to resolve and ensure models are available on target hosts before instance creation.

The README and ROADMAP describe three schemes: `repo://`, `huggingface://`, `local://`. The exact syntax, resolution behavior, caching semantics, and error handling are not yet specified.

## Goal

- Create a specification document in the training-platform-project (docs repo). Suggested path: `docs/specs/model-source-uri.md`.
- Document the following URI schemes:
  - **`repo://`** – Data Repository artifacts. Format: `repo://{name}:{version}`. Examples: `repo://iris-osl:v3`, `repo://iris-tickets:2026-03`. Resolution: query Data Repository API (`GET /api/resolve?uri=...`), obtain `harbor_ref`, pull directly from Harbor (ORAS) to host's managed models directory. Data Repository is metadata-only; blobs live in Harbor. Caching: by version; skip if already present.
  - **`huggingface://`** – HuggingFace Hub. Format: `huggingface://{org}/{model}` or `huggingface://{model}`. Examples: `huggingface://microsoft/phi-3`, `huggingface://meta-llama/Llama-2-7b-hf`. Resolution: download via HuggingFace Hub (or `huggingface_hub` library) to host's managed models directory. Caching: by model ID; skip if already present.
  - **`local://`** – Local filesystem. Format: `local://{path}` or `local:///absolute/path`. Examples: `local:///opt/models/iris.gguf`, `local://./models/my-model`. Resolution: validate path exists within allowed base (e.g. `MODELS_DIR` or configured root), return resolved absolute path. No download. Backward compatible with existing `model` / `model_id` paths.
- Document resolution behavior: who resolves (solar-control vs solar-host), when resolution happens (before instance creation), idempotency.
- Document caching: when to skip download, how to detect "already present", cache invalidation.
- Document error handling: URI parse errors, resolution failures (404, network error), disk full, permission denied. Return clear error messages to the caller.
