# S-061: vLLM serving backend

## Description

Solar serves generation models through llama.cpp (GGUF), the HuggingFace
servers, and SGLang (CUDA). vLLM is the missing second CUDA engine: it is the
reference high-throughput serving stack for the same HuggingFace checkpoints,
it is the engine the SM120 fleet needs for several model / quantization paths
SGLang cannot run (NVFP4 MoE kernels, MTP speculative decoding on
GLM-5.3-Flash), and vLLM-first quantizations keep appearing for new open
models. Operators currently launch vLLM by hand on the GPU hosts, so those
instances get no managed lifecycle, no gateway routing, and no token
accounting.

This issue adds `vllm` as a first-class backend type across solar-host,
solar-control and the webui, mirroring the SGLang integration: typed config
fields for the stable knobs plus `extra_args` / `extra_env` escape hatches,
log-gated readiness, Prometheus usage accounting with per-request
finalization, context probing, CUDA-only placement pinning, and
field-ownership validation.

## Goal

- **solar-host** — `VllmConfig` (`solar_host/models/vllm.py`) and
  `VllmRunner` (`solar_host/backends/vllm.py`):
  - venv resolution via a new `VLLM_VENV_PATH` setting (console script
    `bin/vllm`, then the venv interpreter running `vllm.entrypoints.cli.main`,
    then `vllm` on PATH); advertised in `supported_backends` only on NVIDIA
    hosts where the executable resolves.
  - `build_command`: `vllm serve <model_path>` with host-managed `--host`,
    `--port`, `--api-key`, `--served-model-name`,
    `--enable-prompt-tokens-details`; typed flags next; `extra_args` appended
    last.
  - `build_env`: venv activation (`VIRTUAL_ENV`, `PATH`, `PYTHONHOME=""`)
    over the base GPU-visibility block, `extra_env` last.
  - readiness on `Application startup complete`; context probe via
    `GET /v1/models` → `max_model_len`; vision capabilities from the
    checkpoint config (`capabilities_for_config` gains `vllm`).
  - usage accounting from `/metrics` (`vllm:prompt_tokens_total`,
    `vllm:generation_tokens_total`, `vllm:prompt_tokens_cached_total`,
    `vllm:num_requests_running`, `vllm:num_requests_waiting`,
    `vllm:kv_cache_usage_perc`): busy from `num_requests_running`,
    per-request `GenerationMetrics` from 0→1/1→0 counter deltas, decode TPS
    from the engine stats log line.
- **solar-control** — `vllm` in `VALID_BACKEND_TYPES`; `_VLLM_FIELDS`
  ownership table; CUDA-only placement pin (mirrors SGLang); reserved-args
  validation; `speculative_config` JSON canonicalization; GPU count derived
  from `tensor_parallel_size` × `pipeline_parallel_size`; `model_path`
  mapping in the create/migrate helpers; cache-aware usage fallback
  membership in the gateway.
- **solar-webui** — a vLLM backend card plus `VllmConfigFields`; defaults;
  the `intentValidation.ts` mirror; model-path requirement; per-host
  availability gating (host accelerator + advertised backends).
- **Tests and docs** — unit tests on all three apps;
  `deployment-intent.md` (§4.7.6) and `gpu-aware-placement.md` amendments;
  solar-host README and `.env.example`.

## Additional Notes

- Repo: `solar` monorepo; `apps/solar-host`, `apps/solar-control`,
  `apps/solar-webui`.
- Served name: vLLM performs no `:` parsing (exact-match model lookup; no
  LoRA-separator syntax in the request path), so the alias is served verbatim
  and solar-control needs no request translation — unlike SGLang. Covered by
  a colon-alias smoke test during verification; if a build ever changes this,
  fall back to the SGLang translation mechanism, which control already
  supports generically.
- Typed fields: `tensor_parallel_size`, `pipeline_parallel_size`,
  `max_model_len`, `gpu_memory_utilization`, `max_num_seqs`,
  `max_num_batched_tokens`, `dtype`, `quantization`, `kv_cache_dtype`,
  `moe_backend`, `trust_remote_code`, `enforce_eager`,
  `enable_prefix_caching`, `speculative_config` (JSON object),
  `tool_call_parser`, `reasoning_parser`, `enable_auto_tool_choice`.
- Reserved `extra_args` flags (host-managed): `--host`, `--port`,
  `--api-key`, `--model`, `--served-model-name`,
  `--enable-prompt-tokens-details` / `--no-enable-prompt-tokens-details`,
  `--disable-log-stats`.
