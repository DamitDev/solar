# U-007: Add model and dataset upload to the Solar WebUI

## Description

Some models we train cannot be published to HuggingFace, so operators need a way to publish a model they already hold on their machine. Today the Solar WebUI can browse the catalog (U-002) and see what is on each host (`/storage`), but there is no upload path anywhere in the product — the only ingestion route is a full SuperNova training pipeline.

S-047 adds the upload relay to Solar Control: a session is created, each file is streamed through Solar Control into Harbor, and the version is registered in the Data Repository on completion. This issue is the UI for that flow.

Two constraints shape the design. First, model and dataset uploads must be distinct explicit choices rather than inferred from folder contents, because the category determines the registration endpoint, the OCI config media type, and the metadata form — and datasets have a `format` field the Data Repository validates against a closed set. Second, a browser cannot read a typed filesystem path; it can only receive files the user explicitly grants through a picker.

## Goal

- Add an `/upload` route and a navigation entry, following the existing router and `Navigation.tsx` patterns.
- Step 1 — category: an explicit **Model** / **Dataset** choice that drives everything downstream, with a per-category requirements panel:
  - Model: expects a HuggingFace-format directory (`config.json` plus weights) or one or more `.gguf` files. Warn — do not block — when neither is present, since Solar Host will not be able to serve such an artifact.
  - Dataset: `format` is required and constrained to `parquet`, `hdf5`, or `json`, because the Data Repository rejects anything else on registration. Warn when no file extension matches the declared format.
- Step 2 — folder selection: use `<input type="file" webkitdirectory directory multiple>`. Derive each artifact-relative path from `webkitRelativePath`, stripping the first segment (the chosen folder's own name) so the artifact root is the folder's contents. A `FileList` contains only files, so directories never enter the artifact by construction.
- Filter out common junk automatically and show the exclusion list to the user: `.git/**`, `.gitignore`, `.gitattributes`, `.DS_Store`, `Thumbs.db`, `desktop.ini`, `__pycache__/**`, `*.pyc`, `*.tmp`, `*.part`, `*.lock`, `.ipynb_checkpoints/**`. List every remaining file with its relative path and size, individually deselectable, with a running total and file count.
- Validate client-side before submitting: artifact name against `^[a-z0-9][a-z0-9._-]{0,254}$`, version against `^[A-Za-z0-9][A-Za-z0-9._-]{0,127}$` and not the reserved `latest`, non-empty selection, and no path that is absolute or contains `..`.
- Step 3 — metadata: category-specific form (description, and for models the lineage `parent_model` / `source_dataset` plus optional training config and eval metrics JSON; for datasets the format, record count, and source).
- Step 4 — progress: per-file state and an aggregate byte progress bar with estimated time remaining. Use `XMLHttpRequest` rather than `fetch`, because `upload.onprogress` is the only reliable source of upload progress. Cap concurrency at 2–3 files so one large shard does not stall the queue. Allow per-file retry, guard navigation with `beforeunload` while uploading, and abort the session on cancel.
- On success, link to the new version in the catalog.
- Add typed API client methods for the five S-047 endpoints in `src/api/client.ts` and the corresponding types in `src/api/types.ts`.
- Follow existing UI conventions: Nord theme classes, `lucide-react` icons, `cn()` from `src/lib/utils.ts`, and the loading/error patterns from `Dashboard.tsx` and `GatewayDashboard.tsx`.
- Run `make test-solar-webui` (ESLint, Prettier, Vitest) and `pnpm --filter solar-webui build`.

- Repo: `solar-webui` at `/mnt/nvme/AI/damit-aiops/solar/apps/solar-webui`
- Key files: `src/App.tsx`, `src/components/Navigation.tsx`, `src/api/client.ts`, `src/api/types.ts`, new `src/components/ArtifactUpload.tsx` with step components under `src/components/upload/`, and `src/lib/uploadPaths.ts` for path derivation and validation.
- Contract: [docs/specs/artifact-upload.md](../../docs/specs/artifact-upload.md) §5
- Plan: [docs/plans/artifact-upload-implementation.md](../../docs/plans/artifact-upload-implementation.md) §4
- Depends on S-047. Can be developed in parallel against a locally running Solar Control.
- **Topology constraint:** the WebUI must not call the Data Repository or Harbor directly. Uploads go through the existing `/api/control` proxy, which injects the management API key — no new proxy target or credential is needed.
- `showDirectoryPicker()` (File System Access API) would give a nicer picker but is Chromium-only. It may be added later as a progressive enhancement; `webkitdirectory` is the baseline.
- The deployment side (ingress body size, request buffering, proxy timeout) is part of S-047's `aiops-k8s` change. Without it, uploads fail at the 1 MB nginx default on the WebUI ingress.
