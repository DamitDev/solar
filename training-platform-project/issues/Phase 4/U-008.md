# U-008: Add catalog delete UI to the Solar WebUI

## Description

The catalog page (`ModelCatalog`) is read-only today. S-048 adds the delete relay to Solar Control; this issue is the UI for it. Operators need to remove mistaken or obsolete uploads from the catalog — both whole repositories and single versions.

The detail view only shows `versions_count` and `latest_version` today, so version-level delete requires a version list end-to-end: `GET /api/catalog/models/{name}/versions` returns each version with its per-version `solar` block (running instances, deployed hosts), so the UI can show what blocks a row before the user attempts deletion.

Deletion is destructive and unrecoverable (Harbor blobs are removed), so the UI must confirm deliberately: a two-phase modal mirroring `StorageDeleteModal`, with a blocked state rendering the 409 blocking instances (confirm disabled), a warning when the model is still cached on hosts (host copies remain until evicted), and typed name confirmation for whole-repository delete. The modal reports per-version results on partial failure.

## Goal

- Add `CatalogModelVersion`, `CatalogVersionsResponse`, `CatalogDeleteResult` types to `src/api/types.ts`.
- Add `getCatalogModelVersions(name)`, `deleteCatalogModelVersion(name, version)`, `deleteCatalogModel(name)` to `src/api/client.ts`.
- `ModelDetail.tsx`: new **Versions** section lazily fetching on open — one row per version (version, size, created, deployment badge) with a trash action; a "Delete repository" action next to the existing Deploy button.
- New `src/components/CatalogDeleteModal.tsx` modelled on `StorageDeleteModal` (two-phase confirm → results), with: blocked state rendering the 409 instance list and a disabled confirm; a warning when the model is still cached on hosts; typed name confirmation for whole-repository delete; `bg-nord-11` destructive button per existing convention.
- `ModelCatalog.tsx`: `onDeleted` → `fetchCatalog()` (the `StoragePage.handleDeleteDone` pattern). No toast library exists; feedback stays inline.
- Run `make test-solar-webui` (ESLint, Prettier, Vitest) and `pnpm --filter solar-webui build`.
