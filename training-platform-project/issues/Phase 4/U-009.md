# U-009: webui — process logs on failures, pull progress, field-level validation errors

## Description

Start failures surfaced only as a 502 banner: no link to the process log
that explains the exit, no progress while a model pull runs, and intent
validation errors were a generic banner instead of field-level hints.

## Goal

- Intent detail shows `last_error.log_tail` (host-attached log lines) and a
  "View process logs" button that opens the LogViewer for the failed
  instance (`last_error.instance_id`/`host_id`).
- A `recoverable` last_error gets an amber "host still working" badge.
- Live model pull progress: a progress bar on the intent detail while
  `downloading`, a compact `↓ N%` indicator on the intents table, terminal
  `completed`/`failed` lines.
- Intent form: server-side field-level validation errors render inline next
  to the client-side ones; advisory warnings from create/update are shown
  as a "Saved with warnings" notice.
- `status.shortfall_reason` is shown in the partial-fulfillment banner;
  `status.strategy_progress.message` as a secondary line on the table.

## Additional Notes

Backed by S-049 (drift), S-051 (pull progress), S-052 (validation).
The event-driven endpoint pages use `useFallbackPolling`
(`src/hooks/useFallbackPolling.ts`): events update the cache, REST polling
runs only while the event stream has not delivered data.
