# U-011: webui — intent form error routing and advisory warnings on create

## Description

Two ways the intent form withheld feedback the API had already produced.

**Error routing.** The form's error banner filtered out any field that was
expected to render its own inline error, using a hand-maintained list of
field names. Three entries named slots that only render under a condition
which is false in exactly the configuration that produces the error —
`backend.mmproj` renders only in LLM mode but the error fires outside it,
`backend.model_file` renders only for llama.cpp but the error fires for
other backends, `backend.device` renders only for HuggingFace but the
error fires for llama.cpp. The message was stripped from the banner and
had no slot to appear in, so a 422 surfaced as an empty red box. Two
entries in the list named fields with no inline slot at all.

A field error inside a collapsed section, or below the fold in a
`max-h-[90vh]` scrolling modal, had the same effect: the submit appeared
to do nothing.

**Advisory warnings on create.** Fleet-aware validation returns advisory
warnings in the create response (S-052). The list page discarded the
response body and navigated to the detail page, which re-fetches through
an endpoint that does not recompute advisories — so the detail page's
warning branch was unreachable and the warnings were never shown. The
warnings are response-only by design and correctly not persisted.

## Goal

- Replace the hand-maintained banner filter with render tracking: the
  inline-error helper registers each field it renders, and the banner
  keeps any error whose slot did not mount. The list cannot drift from the
  form again.
- On submit failure, open any collapsed section holding a field error and
  scroll the first error into view.
- Carry create-response warnings across the redirect in navigation state,
  seed the detail page from it, and clear it so a reload does not
  resurrect a dismissed advisory. Drop the now-dead re-fetch branch.
- For edits, show the warnings as an inline notice on the list row rather
  than routing the user away from the list.

## Additional Notes

Do **not** make `GET /api/intents/{id}` recompute advisories: that would
put a fleet scan on every detail poll.

Unit coverage: unmounted-slot and collapsed-section cases in
`src/components/__tests__/IntentFormModal.test.tsx`, and a new
`IntentWarnings.test.tsx` covering create → redirect → dismiss, the
no-resurrection-on-reload case, and the inline row notice on edit.
