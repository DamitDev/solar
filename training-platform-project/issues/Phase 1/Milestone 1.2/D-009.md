# D-009: Implement dataset registration endpoint

## Description

Training datasets (Parquet, HDF5, JSON) are stored in Harbor alongside models as OCI artifacts. When a consumer pushes a dataset to Harbor via ORAS, it registers the artifact with the Data Repository. The registration flow mirrors model registration (D-007): accept harbor_ref + metadata, verify the artifact exists in Harbor, create the metadata record in PostgreSQL.

## Goal

- Implement `POST /api/datasets/{name}/versions`. Same pattern as D-007 (model registration).
- Request body: `harbor_ref` (required, e.g. `imgrepo.damit.hu/supernova/iris-tickets:2026-03`), `version` (optional — auto-increment if not specified), `checksum`, `size_bytes`, `metadata` (optional: `description`, `format` — parquet, hdf5, json).
- Flow: (1) Validate. (2) `HarborClient.verify_artifact(harbor_ref)`. (3) Create `artifacts` (category=dataset) and `artifact_versions` rows. (4) Return 201.
- Reuse shared logic from D-007. Factor into generic `register_artifact_version()` if possible — the only difference is `category`.
- If artifact `{name}` already exists with a different category, reject with 409.
