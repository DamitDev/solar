# D-007: Implement model registration endpoint

## Description

When a consumer (e.g. `supernova-step-upload-model`) pushes a trained model to Harbor via ORAS, it then registers the artifact with the Data Repository. The registration endpoint accepts the harbor_ref and metadata, verifies the artifact exists in Harbor, and creates the metadata record in PostgreSQL. D-006 provides the Harbor verification layer; D-005 provides the schema.

## Goal

- Implement `POST /api/models/{name}/versions`. Request body: `harbor_ref` (required, e.g. `imgrepo.damit.hu/supernova/iris-osl:v3`), `version` (optional — auto-increment if not specified), `checksum` (optional, SHA-256 of blob), `size_bytes` (optional), `metadata` (optional JSONB: `training_config`, `eval_metrics`, `lineage`).
- Flow: (1) Validate request. (2) Call `HarborClient.verify_artifact(harbor_ref)` to confirm the artifact exists in Harbor (HEAD request). Reject with 404/400 if not found. (3) Create/update `artifacts` (category=model) and `artifact_versions` rows in Postgres. (4) Return 201 with `{"name": "iris-osl", "version": "v3", "harbor_ref": "...", "category": "model"}`.
- Version: auto-increment (v1, v2, ...) if client does not specify, or client-specified (e.g. `2026-03`). Support both.
- If artifact `{name}` does not exist yet, create it with `category=model`. If it exists, verify category matches (reject registering a model name that's already a dataset).
- Return 409 if version already exists for this artifact.

## Additional Notes

- Repo: `data-repository` at `/mnt/nvme/AI/damit-aiops/data-repository`
- Depends on D-005 (schema), D-006 (Harbor verification).
- D-008 (version detail) and D-014 (resolve) consume this data. D-015 deploys; N-029 (retention) may delete.
