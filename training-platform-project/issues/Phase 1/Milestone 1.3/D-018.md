# D-018: Add model catalog endpoint to solar-control for Solar WebUI

## Description

Solar WebUI needs a model catalog view that reflects the authoritative Data Repository model list while also showing what Solar knows operationally: whether models are already available on hosts, deployed as running instances, or currently unavailable for immediate use.

Solar Control should expose a catalog endpoint that proxies Data Repository's model listing from D-013 and enriches each model with Solar deployment and availability data. The Data Repository remains the authority for catalog metadata and versions; Solar Control adds runtime context only. If the S-020 availability endpoint is not available yet, this issue should either depend on it practically or return an explicit empty/minimal availability enrichment until S-020 lands.

## Goal

- Implement `GET /api/catalog/models` in `solar-control` at `/mnt/nvme/AI/damit-aiops/solar/apps/solar-control`.
- Proxy Data Repository's D-013 model list endpoint, preserving pagination and common query parameters such as `search`, `limit`, and `offset` where supported.
- Return Data Repository model metadata as the base catalog source; do not create a separate Solar-owned catalog of repository models.
- Enrich each model with Solar runtime data such as running instance count, deployed host IDs/names, availability on hosts, and an availability/deployment status suitable for Solar WebUI.
- Use S-020 (`GET /api/models/availability`) as the practical source for host availability enrichment when available.
- If S-020 is not implemented, define a minimal response shape with empty or `unknown` availability fields so Solar WebUI can integrate without misleading operators.
- Handle Data Repository unreachable, invalid query params, and partial Solar enrichment failures with clear status codes or response metadata.
- Add or update tests for proxy pagination/search, successful enrichment, Data Repository failure, and missing/unavailable S-020 enrichment behavior.

## Additional Notes

- Repo: `solar-control` at `/mnt/nvme/AI/damit-aiops/solar/apps/solar-control`
- Related repo: `solar-webui` at `/mnt/nvme/AI/damit-aiops/solar/apps/solar-webui` as the downstream consumer of the endpoint.
- Depends on D-013 (Data Repository search and browse endpoints) and D-015 / Data Repository reachability from Solar Control.
- Practical enrichment dependency: S-020 (Solar Control model availability query). Running instance enrichment may also reuse existing Solar Control instance state/routes if already available.
- Environment prerequisites: configure Solar Control with the Data Repository base URL and any required inter-service API key; ensure Solar Control can access host/instance state for enrichment.
- Downstream consumers: Solar WebUI model catalog, operator workflows that select a repository model for deployment, and future SuperNova/Solar operational dashboards.
