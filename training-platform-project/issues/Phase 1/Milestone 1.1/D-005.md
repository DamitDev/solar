# D-005: Provision PostgreSQL schema from D-002 in the cluster

## Description

D-002 designs the schema; D-004 scaffolds the project. This issue provisions the schema in the cluster's PostgreSQL and sets up Alembic for future migrations. The Data Repository will use this schema for artifact metadata (D-007, D-009, D-011, etc.).

The AIOps platform uses PostgreSQL in the cluster. The Data Repository needs a database (or schema) and the tables from D-002.

## Goal

- Add schema creation to the Data Repository project. Use the design from D-002: `artifacts` (with `category` field), `artifact_versions` (with `harbor_ref`), `artifact_metadata` (or equivalent).
- Implement `ensure_schema()` or similar: run `CREATE TABLE IF NOT EXISTS` on startup. Alternatively, use Alembic for initial migration.
- Set up Alembic: `alembic init`, first migration that creates the tables. Document how to run migrations (local, in-cluster).
- Ensure the Data Repository connects to the correct database. `DATABASE_URL` should point to the cluster Postgres (or a dedicated DB for data-repository). Document any required DB creation (e.g. `CREATE DATABASE data_repository`).
- Integrate schema provisioning into app lifespan: on startup, run migrations or `ensure_schema()` before accepting requests.
- Add migration instructions to README.

## Additional Notes

- Repo: `data-repository` at `/mnt/nvme/AI/damit-aiops/data-repository`
- Depends on D-002 (schema design), D-004 (project scaffold).
- D-007, D-009, D-011, etc. depend on this for metadata storage.
