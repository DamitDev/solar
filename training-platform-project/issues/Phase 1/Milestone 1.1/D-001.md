# D-001: Create `supernova` project in Harbor

## Description

Harbor (`imgrepo.damit.hu`) is the existing artifact registry for the AIOps platform. Docker images and Helm charts are stored there. The Data Repository uses Harbor as blob storage — models and datasets are stored as OCI artifacts via ORAS. Consumers (step containers, Solar Control) push/pull directly to/from Harbor. A dedicated project must exist before any artifacts can be pushed.

Each artifact (model or dataset) becomes a repository directly under the `supernova` project. For example, `imgrepo.damit.hu/supernova/iris-osl:v3` is a model, `imgrepo.damit.hu/supernova/iris-tickets:2026-03` is a dataset. The category (model vs dataset) is tracked in Data Repository metadata, not in the Harbor path. Repositories are created automatically on first push.

## Goal

- Create the `supernova` project in Harbor (via Harbor UI or API). Project lead has direct authority on Harbor.
- Configure access: Create a robot account (or user credentials) for pushing/pulling artifacts. These credentials will be used by:
  - Data Repository service (for artifact verification via Harbor API)
  - Step containers running on Solar Hosts (for direct ORAS push/pull)
  - Solar Control (for `repo://` resolver ORAS pulls)
- Document the credentials location (Kubernetes secret, env var) for D-004/D-006 and step container images (S-028, S-029, S-030).
- Ensure the project allows custom OCI media types: `application/vnd.supernova.model.*`, `application/vnd.supernova.dataset.*` (Harbor typically allows arbitrary media types for OCI artifacts).

## Additional Notes
