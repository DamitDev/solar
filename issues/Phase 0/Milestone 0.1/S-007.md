# S-007: Update Solar WebUI host cards to display roles, GPU type, and resource availability

## Description

Solar WebUI's `HostCard` component (`solar-webui/src/components/HostCard.tsx`) displays host name, URL, status, instance counts, model categories, last seen, and memory usage (VRAM/RAM bar). It does not show host roles, GPU type, or disk/resource availability.

SuperNova operators need to see at a glance which hosts are training-capable, what acceleration they use, and how much disk/memory is free.

## Goal

- Extend the Host type in `api/types.ts` to include `roles?: string[]`, `gpu_type?: string`, and resource fields (`disk`, `available_gb` or equivalent) if the API provides them.
- Update `HostCard` to display:
  - **Roles**: badges or tags (e.g. "inference", "training") in the host header.
  - **GPU type**: label (e.g. "NVIDIA CUDA", "Apple MPS", "CPU") near the memory section.
  - **Resource availability**: disk (total/used/available) and available memory, if present. Reuse or extend the existing memory bar pattern for disk.
- Ensure the Dashboard and any table view (UnifiedTable) show roles and GPU type when available.

## Additional Notes

- Repo: `solar-webui` at `/mnt/nvme/AI/solar/solar-webui`
- Key files: `src/components/HostCard.tsx`, `src/api/types.ts`, `src/hooks/useInstances.ts` (host data source)
- API: `GET /api/hosts` from solar-control. Host data is also received via Socket.IO (`host_status`, `host_health`). Ensure the EventStreamContext merges resource fields into host state.
- Depends on S-006 (API returns roles, gpu_type, resource availability).
