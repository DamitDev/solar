# S-005: Extend host data model in Redis and PostgreSQL to store `roles`, `gpu_type`, and extended resource fields

## Description

Solar Control stores host data in PostgreSQL (`hosts` table: id, name, url, api_key, status, last_seen, memory, created_at) and Redis (connection state: sid, instances). The Host model (`app/models.py`) has `memory: Optional[MemoryInfo]` but no `roles`, `gpu_type`, or disk/resource fields. Host registration and `host_health` events do not persist these attributes.

SuperNova requires role-based host filtering and resource-aware scheduling. The control plane must persist and serve `roles`, `gpu_type`, and extended resource data (disk, available memory) from the moment a host registers.

## Goal

- Add `roles` (JSONB array, e.g. `["inference", "training"]`), `gpu_type` (TEXT, e.g. `nvidia_cuda`), and extended resource fields to the PostgreSQL `hosts` table. Consider: `disk_total_gb`, `disk_used_gb`, `disk_available_gb`, `memory_available_gb`.
- Update the Host Pydantic model in `app/models.py` to include these fields.
- Update `HostDB` in `app/database/hosts.py`: `add_host`, `update_host_*`, `_row_to_host`.
- Update the host registration handler in `app/socketio_app/host_handlers.py` to accept and persist `roles` and `gpu_type` from the registration event. Update `host_health` handler to persist disk and available memory when provided.
- Ensure Redis-backed host state (if any) is updated if roles/resources are cached there.
