# S-041: Implement intent reconciliation engine

## Description

Intent APIs store desired state, but Solar Control also needs a reconciliation loop that compares those intents with the actual running instances across hosts. The reconciler is responsible for creating, migrating, and stopping instances to make actual state match desired state.

This is a Solar Control responsibility. Solar Hosts provide local execution primitives only; they should not independently decide placement or cluster-wide desired state.

## Goal

- Implement a reconciliation engine in solar-control that periodically or in response to events processes active intents.
- Compare desired state from intents with current state from Solar Control host/instance status.
- Compute actions needed to satisfy each intent: create instance, stop instance, migrate instance, or no-op.
- Enforce one replica per host for the same deployed model/alias.
- Use a placement policy shared with or aligned to S-038 instead of duplicating host selection logic.
- Use S-019 model distribution before creating an instance on a host that lacks the required model.
- Use S-037 migration when moving an existing instance is required and allowed by priority/policy.
- Respect instance priorities `production`, `staging`, and `ephemeral` during placement and displacement decisions.
- Update intent status with reconciliation progress, last error, observed replica count, and timestamps.
- Make reconciliation idempotent so retries do not create duplicate instances.

## Additional Notes

- Repo: `solar-control` at `/mnt/nvme/AI/solar/solar-control`
- Key files likely: intent service, reconciliation/background task module, instance management service, resource/placement policy service, host client, database models.
- Roadmap dependencies: S-040 (intent API) and S-037 (migration).
- Practical dependency: S-035 should be available so the reconciler can make placement decisions from an aggregated resource view rather than stale or incomplete host data.
- Downstream consumers: S-042 (deployment strategies), U-003 (intent UI), N-020/N-021 (SuperNova deployment automation/status).
- Keep reconciliation under Solar Control. SuperNova submits desired state and observes status; it does not perform host placement or direct host operations.
