# S-042: Implement rolling and immediate deployment strategies

## Description

The reconciliation engine needs explicit deployment strategies for changing an existing alias from one model version/configuration to another. The first supported strategies are `rolling` and `immediate`.

Strategies should be implemented inside Solar Control reconciliation. Solar Host should only execute local stop/start/pull operations requested by Solar Control, and SuperNova should only submit deployment intents and observe status.

## Goal

- Implement `rolling` strategy in Solar Control reconciliation: update one host/replica at a time, wait for the replacement instance to become healthy, then proceed to the next.
- Implement `immediate` strategy: stop all existing managed replicas for the intent, then start replacements according to placement policy.
- Store and report per-strategy progress in intent status, including current step, updated replicas, failed replicas, and last error.
- Ensure model files are pulled through the existing model distribution/pull flow before a replacement instance is started.
- Enforce one replica per host for the same deployed model/alias during both rolling and immediate updates.
- Respect priority and placement constraints while selecting replacement hosts.
- Define clear failure behavior for each strategy, including whether already-updated replicas remain running after a partial failure.
- Add tests or implementation notes that cover scale up, scale down, model version change, and failed health check scenarios.

## Additional Notes

- Repo: `solar-control` at `/mnt/nvme/AI/solar/solar-control`
- Key files likely: reconciliation engine from S-041, intent status models, instance management service, health/status checks, placement policy service.
- Depends on S-041 (intent reconciliation engine).
- Downstream consumers: N-020 (SuperNova deployment trigger), N-021 (deployment status tracking), U-003 (Solar WebUI intent submission).
- `rolling` should prefer maintaining service availability for `production` intents. `immediate` is acceptable for fast replacement where downtime is expected or requested.
- Keep strategy names and priority names consistent with S-039/S-040: `rolling`, `immediate`, `production`, `staging`, `ephemeral`.
