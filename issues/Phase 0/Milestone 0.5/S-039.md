# S-039: Design declarative intent API specification

## Description

Solar needs a declarative deployment model so clients can describe desired inference state instead of manually creating instances on specific hosts. The intent API will become the contract used by Solar WebUI and SuperNova deployment automation.

This issue produces the specification before implementation. It should define the desired-state schema, lifecycle, reconciliation semantics, placement constraints, deployment strategies, and error/status model.

## Goal

- Document the intent schema, including model source URI, deployed alias, replica count, priority, strategy, resource requirements, and placement constraints.
- Define supported priorities using `production`, `staging`, and `ephemeral`.
- Define supported deployment strategies for the first implementation, including `rolling` and `immediate`.
- Specify how Solar Control enforces one replica per host for the same deployed model/alias.
- Specify how model sources are resolved and distributed through existing Solar Control and Solar Host pull flows.
- Define intent status fields, reconciliation status, error reporting, timestamps, and useful audit metadata.
- Define create/list/delete API shapes for S-040 and reconciliation behavior for S-041/S-042.
- Include examples for common flows: initial deployment, scale up/down, model version update, delete intent.
