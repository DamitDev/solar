# S-033: Add active job step awareness to solar-control host status

## Description

Solar Control host status should show active job step workloads alongside inference instances. Operators and scheduling logic need one aggregated view of what each host is doing before assigning more work.

Solar Control should aggregate this state from Solar Host job status/events; it should not execute containers itself.

## Goal

- Extend Solar Control's host status model/response with active jobs and active step summaries per host.
- Include job ID, current step, status, resource hints or reserved resources where available, start time, and recent terminal state for completed/failed jobs if retained.
- Update host status aggregation from S-032 proxied submissions and lifecycle events.
- Broadcast host status changes to Solar WebUI clients when job activity starts, advances, completes, fails, or is cancelled.
- Ensure inference instance status remains backward compatible for existing consumers.

## Additional Notes

- Repo: `solar-control` at `/mnt/nvme/AI/solar/solar-control`
- Key files likely: host status models, host aggregation service, Socket.IO broadcast handlers, API response schemas.
- Depends on S-032 (job submission proxy).
- Consumed by Solar WebUI operations views, SuperNova scheduler visibility, and future resource coordination work in Milestone 0.5.
