# S-019: Implement model distribution in solar-control

## Description

Solar Control proxies instance creation to individual hosts. There is no capability to copy a model from one host to another. Instance migration (S-037) and resource coordination require models to be available on the target host; today that would require manual copying. Model distribution automates this: download from source host, upload to target host.

S-015 and S-016 provide the upload/download APIs on solar-host. Solar-control can call them via aiohttp, passing the host API key.

## Goal

- Implement `POST /api/models/distribute` in solar-control. Request body: `source_host_id`, `target_host_id`, `model_name`. Optional: `model_name` could be a list for batch distribution.
- Flow: (1) Resolve source and target hosts from DB. (2) Call `GET {source_host.url}/models/{model_name}/download` with source host's API key, stream response. (3) Call `POST {target_host.url}/models/upload` with target host's API key, stream the bytes to the upload. (4) Return 200 with summary: model name, source, target, size.
- Validate target host has sufficient disk space before starting (query target's `/health` for disk.available, compare with model size from `GET /models` on source).
- Handle errors: host unreachable, 404 (model not found), 507 (disk full), auth failures. Return appropriate HTTP status and message.
- Require management API key. Route under `/api/models/` (create new router or add to management routes).

## Additional Notes

- Repo: `solar-control` at `/mnt/nvme/AI/solar/solar-control`
- Key files: new `app/routes/management/models.py` or `app/routes/models.py`, `app/database/hosts.py` (get host by id)
- Depends on S-015 (upload), S-016 (download).
- Used by S-037 (instance migration) to ensure model is on target before recreating instance.
