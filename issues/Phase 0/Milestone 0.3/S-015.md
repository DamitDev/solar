# S-015: Implement `POST /models/upload` on solar-host

## Description

Solar Host has no API to receive model uploads. Models are expected to exist on disk before instance creation. The HuggingFace resolver (S-012) and model distribution (S-019) need to push model files to hosts programmatically. Today this would require manual scp/rsync or similar.

S-009 provides the managed models directory and manifest. This issue adds a streaming upload endpoint to receive model files and directories.

## Goal

- Implement `POST /models/upload` on solar-host. Accept multipart/form-data or streaming request body. Support both single-file and directory uploads (e.g. tar archive or recursive multipart).
- Target: write to managed models directory (`MODELS_DIR`). Use a subdirectory per model (e.g. `{MODELS_DIR}/{model_name}/`) to avoid collisions.
- Request parameters: `name` (model identifier, required), optional `source_uri` (for manifest), optional `checksum` for integrity verification.
- Include integrity checks: verify checksum (e.g. SHA-256) if provided. Reject upload if checksum mismatch.
- Update manifest after successful upload. Add or update entry with name, path, size_bytes, source_uri, checksum, downloaded_at.
- Use streaming to avoid loading entire model into memory. For large files, stream to temp file then move to final location.
- Require API key authentication.
