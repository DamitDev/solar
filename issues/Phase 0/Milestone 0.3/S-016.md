# S-016: Implement `GET /models/{name}/download` on solar-host

> **Note:** This issue is **deprioritized**. With the updated model source architecture (see `docs/specs/model-source-uri.md`), model distribution uses source-based pulls (hosts pull from Harbor/HuggingFace directly) rather than host-to-host byte transfer. This endpoint is not required for the primary model acquisition or distribution flow. It may be useful for debugging, inspection, or edge cases where a model needs to be extracted from a host.

## Description

Solar Host has no API to download model files from its managed models directory. While model distribution (S-019) no longer requires this endpoint (hosts pull from authoritative sources instead), a download endpoint may be useful for operational tasks: extracting a model for backup, debugging, or transferring to systems outside the Solar ecosystem.

## Goal

- Implement `GET /models/{name}/download` on solar-host. Path parameter `name` identifies the model (slug as in manifest / `GET /models`).
- Response: streaming download of the model. For single-file models: stream the file with appropriate `Content-Type` and `Content-Disposition`. For directory models: stream a tar archive (e.g. `model.tar.gz`) of the model directory.
- Resolve `name` to path via manifest. Return 404 if model not found.
- Include `Content-Length` if known (file size or tar size). For large tars, consider streaming without pre-computing size or using chunked encoding.
- Require API key authentication.
