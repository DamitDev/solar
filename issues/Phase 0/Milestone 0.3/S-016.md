# S-016: Implement `GET /models/{name}/download` on solar-host

## Description

Solar Host has no API to download model files. Model distribution (S-019) requires pulling a model from one host and pushing to another. Without a download endpoint, solar-control cannot fetch model bytes from a host to redistribute.

S-009 provides the managed models directory. Models may be single files (GGUF) or directories (HuggingFace format with multiple files). The download endpoint must support both.

## Goal

- Implement `GET /models/{name}/download` on solar-host. Path parameter `name` identifies the model (as in manifest / `GET /models`).
- Response: streaming download of the model. For single-file models: stream the file with appropriate `Content-Type` and `Content-Disposition`. For directory models: stream a tar archive (e.g. `model.tar.gz`) of the model directory.
- Resolve `name` to path via manifest or directory lookup. Return 404 if model not found.
- Include `Content-Length` if known (file size or tar size). For large tars, consider streaming without pre-computing size or using chunked encoding.
- Require API key authentication.
- Support range requests (`Range` header) for resumable downloads if feasible; otherwise optional.

## Additional Notes

- Repo: `solar-host` at `/mnt/nvme/AI/solar/solar-host`
- Key files: `app/routes/models.py`
- Depends on S-009 (managed models directory, manifest).
- S-018 will add free space validation; the download endpoint is for pulling from host, so disk space is less relevant here (it's the client's concern). S-019 uses this to pull from source host.
