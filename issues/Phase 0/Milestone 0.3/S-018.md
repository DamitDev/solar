# S-018: Add free space validation before model operations

## Description

Solar Host's model upload (S-015) and download (S-016) can fail or cause disk-full conditions if the target has insufficient space. S-003 adds disk space reporting to `/health` (total, used, available for models directory). This issue adds proactive validation before uploads and optionally before downloads (when solar-host is the target of a distribution).

Validation should happen before streaming begins to avoid partial writes and wasted bandwidth.

## Goal

- Before `POST /models/upload`: compute the size of the incoming upload (from `Content-Length` header or multipart metadata). Compare with available disk space for `MODELS_DIR`. If `available < required`, return 507 Insufficient Storage (or 400) with message: "Insufficient disk space. Available: X GB, required: Y GB."
- For streaming uploads without known size: either reject (require Content-Length) or implement a size limit and abort if exceeded.
- Before model distribution (S-019) upload phase on target host: solar-control should query target host's disk availability (from `/health` or a dedicated endpoint) and compare with model size before initiating the transfer. This may be implemented in S-019; document the contract here.
- Integrate with S-003: use the same disk usage logic (e.g. `psutil.disk_usage(MODELS_DIR)`). Ensure `/health` disk fields are available for solar-control to query.

## Additional Notes

- Repo: `solar-host` at `/mnt/nvme/AI/solar/solar-host`
- Key files: `app/routes/models.py` (upload handler), `app/main.py` (health endpoint if disk not yet added)
- Depends on S-003 (disk reporting), S-015 (upload endpoint to add validation to).
- S-019 (model distribution) should check target host disk before upload; that logic can live in solar-control.
