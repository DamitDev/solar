# S-012: Implement `huggingface://` resolver in solar-control

## Description

Solar Control has no HuggingFace model download capability. HuggingFace-backed instances today require the model to be pre-downloaded on the host (or use `model_id` with HuggingFace's automatic download at runtime). The model source abstraction requires solar-control to resolve `huggingface://` URIs by downloading the model from HuggingFace Hub to the target host's managed models directory.

The host must expose an API to receive uploaded models. S-014 (Milestone 0.3) implements `GET /models` to list models; S-015 implements `POST /models/upload` for streaming upload. S-012 needs a way to push the downloaded model to the host.

## Goal

- Implement the `huggingface://` resolver in solar-control. Input: URI (e.g. `huggingface://microsoft/phi-3`), target `host_id`.
- Resolver logic: (1) Parse URI to extract model ID (e.g. `microsoft/phi-3`). (2) Download model from HuggingFace Hub using `huggingface_hub` library (or equivalent) to a temp directory. (3) Upload to target host via `POST /models/upload` (solar-host). (4) Return resolved path: `local://{models_dir}/{model_slug}` or the path solar-host uses for the uploaded model.
- Check manifest / `GET /models` on host before download: if model already exists (same model ID), skip download and return existing path (cache hit).
- Handle errors: HuggingFace API failures, upload failures, disk full. Propagate clear errors to the dispatcher.
- Add `huggingface_hub` (or `huggingface_hub[torch]` if needed) to solar-control `requirements.txt`.
