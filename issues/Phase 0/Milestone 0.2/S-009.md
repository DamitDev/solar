# S-009: Implement managed models directory on solar-host

## Description

Solar Host currently has no formal "models directory." Llama.cpp instances use arbitrary filesystem paths (`config.model`), and HuggingFace instances use `model_id` (Hub ID or local path). Models are expected to exist before instance creation; there is no programmatic tracking of what is downloaded or where.

SuperNova and the model source abstraction require a dedicated, env-configurable directory where downloaded models live. Solar Control will push models here via upload API (Milestone 0.3); resolvers will download to this directory. A manifest file tracks what is present for cache hits and integrity.

## Goal

- Add `MODELS_DIR` to solar-host Settings (`app/config.py`). Default: `./models` or `{config_file_parent}/models`. Env var: `MODELS_DIR`.
- Create the models directory on startup if it does not exist.
- Implement a manifest file (e.g. `models/manifest.json`) that tracks downloaded models. Schema: `{"models": [{"name": "...", "path": "...", "source_uri": "...", "size_bytes": ..., "checksum": "...", "downloaded_at": "..."}]}`. Update manifest when models are added/removed (this issue creates the structure; S-015/S-016 will perform actual add/remove).
- Expose the models directory path via a helper (e.g. `get_models_dir()`) for use by instance creation, health/disk reporting (S-003), and future `GET /models` (S-014).
- Ensure the manifest is read/written atomically (write to temp, rename) to avoid corruption.

## Additional Notes

- S-003 (disk reporting) can use this path for disk usage. S-014 (GET /models) will list from manifest + directory scan.
