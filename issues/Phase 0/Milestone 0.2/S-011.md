# S-011: Implement URI parser and resolver dispatcher in solar-control

## Description

Solar Control proxies instance creation to solar-host (`POST /api/hosts/{host_id}/instances`). It forwards the request body as-is. There is no model source resolution; clients must ensure the model exists on the host before creating an instance.

The model source abstraction requires solar-control to intercept instance creation (or a dedicated "resolve and create" flow), parse `model_source` URIs, and dispatch to the appropriate resolver. Solar Control resolves metadata (e.g. querying Data Repository for `harbor_ref`), then sends pull commands to Solar Host, which downloads directly from the source.

## Goal

- Implement a URI parser module. Parse scheme and components per spec Section 2.4:
  - `repo://iris-osl:v3` → `{scheme: "repo", name: "iris-osl", version: "v3"}`
  - `huggingface://microsoft/phi-3` → `{scheme: "huggingface", model_id: "microsoft/phi-3"}`
  - `local:///path/to/model` → `{scheme: "local", path: "/path/to/model"}`
- Implement a resolver dispatcher. Given a URI and target host_id, route to the correct resolver:
  - `local://` – Pass through to solar-host. Solar-host resolves `local://` at instance creation time (S-010). No pull needed.
  - `huggingface://` – Delegates to HuggingFace resolver (S-012). Resolver sends `POST /models/pull` to target Solar Host with `{source: "huggingface", model_id, source_uri}`. Solar Host downloads directly from HuggingFace Hub. Returns resolved `local://` path for instance config.
  - `repo://` – Delegates to repo resolver stub (S-013). Stub returns error until Data Repository exists. When completed (D-016): queries Data Repository for `harbor_ref`, then sends `POST /models/pull` to target Solar Host with `{source: "harbor", harbor_ref, source_uri, digest}`.
- Integrate the dispatcher into the instance creation flow. When `model_source` is present in the request, call the dispatcher before proxying to solar-host. Replace `model_source` with the resolved `local://` path.
- Handle resolver errors: return 400/502 with clear message (e.g. "repo:// resolver not yet available", "Model pull failed on host: ...").
