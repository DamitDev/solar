# S-011: Implement URI parser and resolver dispatcher in solar-control

## Description

Solar Control proxies instance creation to solar-host (`POST /api/hosts/{host_id}/instances`). It forwards the request body as-is. There is no model source resolution; clients must ensure the model exists on the host before creating an instance.

The model source abstraction requires solar-control to intercept instance creation (or a dedicated "resolve and create" flow), parse `model_source` URIs, and dispatch to the appropriate resolver: `repo://` → Data Repository resolver, `huggingface://` → HuggingFace resolver, `local://` → local resolver (or pass-through to solar-host).

## Goal

- Implement a URI parser module. Parse scheme and components: `repo://iris-osl:v3` → `{scheme: "repo", name: "iris-osl", version: "v3"}`, `huggingface://microsoft/phi-3` → `{scheme: "huggingface", path: "microsoft/phi-3"}`, `local:///path/to/model` → `{scheme: "local", path: "/path/to/model"}`.
- Implement a resolver dispatcher. Given a URI and target host_id, route to the correct resolver:
  - `local://` – Resolver validates path is allowed on host (or delegates to solar-host). Returns resolved path. May be a no-op (solar-host handles it).
  - `huggingface://` – Delegates to HuggingFace resolver (S-012). Resolver downloads to host's models directory, returns `local://` path or resolved path for instance config.
  - `repo://` – Delegates to repo resolver stub (S-013). Stub returns error until Data Repository exists.
- Integrate the dispatcher into the instance creation flow. When `model_source` is present in the request, call the dispatcher before proxying to solar-host. Replace `model_source` with the resolved `model` or `model_id` (or pass `local://` URI if solar-host resolves it).
- Handle resolver errors: return 400/502 with clear message (e.g. "repo:// resolver not yet available", "HuggingFace download failed: ...").
