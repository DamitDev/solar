# D-003: ORAS Python library evaluation

## Description

The Data Repository will push and pull model/dataset blobs to Harbor using an ORAS-compatible Python client. The exact library, API patterns, and limitations are not yet validated. A proof-of-concept will de-risk the implementation and inform D-006 (ORAS integration layer).

The `oras-py` library (`pip install oras`) provides push/pull for OCI artifacts. Harbor supports OCI artifacts. The POC must verify: authentication, streaming for large files, custom media types, and integrity (checksum verification).

## Goal

- Build a small POC script (or notebook) that:
  1. Pushes a model directory (or single file) as an OCI artifact to Harbor (`imgrepo.damit.hu/supernova/models/test-model:v1`).
  2. Pulls it back to a temp directory.
  3. Verifies integrity (checksum match).
- Use `oras-py` (or alternative: `oras` package). Document installation, auth (login with Harbor credentials), and API usage.
- Test with a multi-file directory (e.g. HuggingFace model format) and a single large file (e.g. GGUF).
- Document findings: API patterns, streaming support, error handling, custom media types (`application/vnd.supernova.model.v1`, `application/vnd.supernova.dataset.v1`), limitations.
- Store POC and findings in data-repository repo (or training-platform-project `docs/poc/`) for reference during D-006.
