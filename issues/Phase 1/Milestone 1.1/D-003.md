# D-003: ORAS Python library evaluation

## Description

Models and datasets are stored in Harbor as OCI artifacts via ORAS. Consumers (step containers, Solar Control) push/pull directly to/from Harbor. The exact library, API patterns, and limitations are not yet validated. A proof-of-concept will de-risk the implementation and inform both the step container images (S-028, S-029, S-030) and the Data Repository's Harbor verification layer (D-006).

The `oras-py` library (`pip install oras`) provides push/pull for OCI artifacts. Harbor supports OCI artifacts. The POC must verify: authentication, handling of large files, custom media types, and integrity (checksum verification).

## Goal

- Build a small POC script (or notebook) that:
  1. Pushes a model directory (or single file) as an OCI artifact to Harbor (`imgrepo.damit.hu/supernova/test-model:v1`).
  2. Pulls it back to a temp directory.
  3. Verifies integrity (checksum match).
- Use `oras-py` (or alternative: `oras` package). Document installation, auth (login with Harbor credentials), and API usage.
- Test with a multi-file directory (e.g. HuggingFace model format) and a single large file (e.g. GGUF).
- Test Harbor API HEAD request to verify artifact existence (this is how Data Repository will validate harbor_refs on registration).
- Document findings: API patterns, large file handling, error handling, custom media types (`application/vnd.supernova.model.v1`, `application/vnd.supernova.dataset.v1`), limitations.
- Store POC and findings in data-repository repo (or training-platform-project `docs/poc/`) for reference during D-006 and step container development.
