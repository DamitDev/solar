# D-004: Scaffold Data Repository FastAPI project

## Description

The Data Repository is a new microservice. It does not exist yet. This issue creates the project structure, configuration, database connection, health endpoint, and container/deployment scaffolding. No business logic yet—just the skeleton for D-005, D-006, and subsequent issues.

## Goal

- Create the `data-repository` project. Suggested structure:
  ```
  data-repository/
  ├── app/
  │   ├── __init__.py
  │   ├── main.py          # FastAPI app, lifespan
  │   ├── config.py        # Settings (DB URL, Harbor URL, etc.)
  │   ├── database/
  │   │   ├── __init__.py
  │   │   ├── connection.py # asyncpg pool
  │   │   └── schema.py    # placeholder for D-005
  │   └── routes/
  │       └── health.py    # GET /health
  ├── requirements.txt
  ├── Dockerfile
  ├── .dockerignore
  └── README.md
  ```
- Configuration: `DATABASE_URL`, `HARBOR_URL` (imgrepo.damit.hu), `HARBOR_USERNAME`, `HARBOR_PASSWORD` (or secret path). Use pydantic-settings.
- Database: asyncpg for PostgreSQL. Connection pool, health check that verifies DB connectivity.
- Health endpoint: `GET /health` returns `{"status": "healthy", "service": "data-repository", "database": "ok"}`.
- Dockerfile: multi-stage, Python 3.11+, uvicorn. Non-root user.
- Helm chart: basic chart with Deployment, Service, ConfigMap, Secret. Placeholder for aiops-k8s integration (D-015 will finalize).
- README: setup, run locally, env vars.
