# D-002: Design PostgreSQL schema for Data Repository metadata

## Description

The Data Repository stores blob data (model files, datasets) in Harbor via ORAS. Metadata — artifact names, versions, category, training config, eval metrics, lineage — must be stored in PostgreSQL. The schema is not yet defined. Solar Control, SuperNova Control, and SuperNova WebUI will query this metadata for resolution, search, and browsing.

Consumers push/pull blobs directly to/from Harbor. The Data Repository only manages metadata and provides a catalog. Each artifact name is globally unique (maps 1:1 to a Harbor repository under `supernova/`).

## Goal

- Design and document the PostgreSQL schema. Suggested tables:
  - **`artifacts`** – Top-level artifact. Columns: `id`, `name` (globally unique), `category` (`model` or `dataset`), `description`, `created_at`, `updated_at`. Unique on `name`.
  - **`artifact_versions`** – Versioned entries. Columns: `id`, `artifact_id` (FK), `version` (tag, e.g. `v1`, `2026-03`), `harbor_ref` (full OCI reference: `imgrepo.damit.hu/supernova/iris-osl:v3`), `size_bytes`, `checksum`, `created_at`, `metadata` (JSONB for training config, eval metrics, etc.).
  - **`artifact_metadata`** – Optional separate table for flexible metadata (description, training_config, eval_metrics, lineage) if not embedded in `artifact_versions`.
- Define indexes for search: by name, category, metadata fields (JSONB GIN), created_at.
- Support lineage: `parent_model_id`, `source_dataset_id`, `source_trainer` in metadata.
- Document the schema in `docs/specs/data-repository-schema.md` or in the data-repository repo.
