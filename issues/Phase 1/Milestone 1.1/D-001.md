# D-001: Create `supernova` project in Harbor

## Description

Harbor (`imgrepo.damit.hu`) is the existing artifact registry for the AIOps platform. Docker images and Helm charts are stored there. The Data Repository will use Harbor via ORAS to store model and dataset OCI artifacts. A dedicated project and repositories must exist before the Data Repository can push artifacts.

The README specifies: `imgrepo.damit.hu/supernova/models/iris-osl:v3`, `imgrepo.damit.hu/supernova/datasets/iris-tickets:2026-03`. This implies a `supernova` project with at least `models` and `datasets` repositories (or a single project with both as OCI artifact paths).

## Goal

- Create the `supernova` project in Harbor (via Harbor UI or API). Project lead has direct authority on Harbor.
- Set up repositories for model and dataset artifacts. In Harbor, projects contain repositories; the convention is `{registry}/{project}/{repository}:{tag}`. For `supernova/models` and `supernova/datasets`, create:
  - Repository `supernova/models` (or project `supernova` with repository `models`)
  - Repository `supernova/datasets` (or project `supernova` with repository `datasets`)
- Configure access: Data Repository service will need credentials (robot account or user) to push/pull. Document the credentials location (Kubernetes secret, env var) for D-004/D-006.
- Ensure the project allows the custom OCI media types that will be used: `application/vnd.supernova.model.*`, `application/vnd.supernova.dataset.*` (Harbor typically allows arbitrary media types for OCI artifacts).

## Additional Notes

- Repo: `infra` – operational task; may involve Harbor UI, aiops-k8s (for secrets), or a runbook in the training-platform-project.
- Harbor URL: `imgrepo.damit.hu`
- D-003 (ORAS POC) depends on this; D-006 (ORAS integration) uses the same project.
