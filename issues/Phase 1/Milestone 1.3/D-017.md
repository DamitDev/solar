# D-017: End-to-end integration test: Data Repository -> repo:// -> Solar Host pull -> inference

## Description

This issue adds an end-to-end integration test proving that a model registered in the Data Repository can be referenced by `repo://`, resolved by Solar Control, pulled directly by Solar Host from Harbor, started as an inference instance, and queried successfully.

The roadmap path uses Solar Control's intent API, which depends on S-040. A minimal end-to-end path can still validate the core repository-to-host flow before the full reconciliation stack is available: upload/register a model, create or request a concrete instance with a `repo://` source, verify Solar Host pulls from Harbor, then run inference. The full materialized intent path additionally needs S-041 and S-042 so that an intent is reconciled into running instances with deployment strategy behavior.

## Goal

- Add an integration test suite in the appropriate test repo/path for cross-service Solar/Data Repository tests, using `/mnt/nvme/AI/damit-aiops/data-repository`, `/mnt/nvme/AI/solar/solar-control`, and `/mnt/nvme/AI/solar/solar-host`.
- Prepare or upload a small test model artifact into Data Repository so it has metadata, a version, and a Harbor-backed blob.
- Resolve and deploy that model through Solar Control using a `repo://{name}:{version}` source URI.
- Verify Solar Control calls Data Repository for resolve metadata and does not proxy model blobs or perform ORAS pull logic itself.
- Verify Solar Host receives the pull instruction, pulls directly from Harbor using ORAS / `harbor-oci-client`, writes/updates its cache manifest keyed by `source_uri`, and starts the instance.
- Run a basic inference request through the normal Solar route and assert a successful response.
- Split the test plan if useful:
  - Minimal repo path: Data Repository registration/resolve -> concrete Solar Control instance creation with `repo://` -> Solar Host pull -> inference.
  - Full intent path: Data Repository registration/resolve -> Solar Control intent submission -> reconciliation creates instance -> Solar Host pull -> inference.
- Document any service startup, seeded credentials, cleanup, and model fixture requirements needed for repeatable execution.
