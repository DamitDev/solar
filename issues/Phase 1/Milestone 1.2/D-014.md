# D-014: Implement URI resolution endpoint

## Description

Solar Control's `repo://` resolver (S-013 stub, D-016 complete) needs to resolve URIs like `repo://iris-osl:v3` to artifact metadata and a download URL. The Data Repository is the authority for `repo://` URIs. This endpoint enables the resolver to fetch metadata and then download the artifact.

## Goal

- Implement `GET /api/resolve?uri=repo://iris-osl:v3` (or `uri=repo://models/iris-osl:v3`). Parse the URI to extract artifact name and version.
- Return JSON: `{"artifact_type": "model", "name": "iris-osl", "version": "v3", "download_url": "https://data-repository.../api/models/iris-osl/versions/v3/download", "size_bytes": ..., "metadata": {...}}`.
- `download_url` should be the full URL to the Data Repository's download endpoint. Solar Control (or the client) will use it to fetch the blob. Consider: relative URL vs absolute. For in-cluster calls, relative may work; for external, absolute with configured base URL.
- Support `repo://models/{name}:{version}` and `repo://datasets/{name}:{version}`. Also support shorthand `repo://{name}:{version}` (default to models).
- Return 404 if artifact or version not found.
- This endpoint is used by Solar Control's repo resolver and by SuperNova job validation (verify URIs exist before job submission).

## Additional Notes

- Repo: `data-repository` at `/mnt/nvme/AI/damit-aiops/data-repository`
- Depends on D-008 (model download URL), D-010 (dataset download).
- D-016 (repo resolver) calls this. N-004 (job submission) validates repo URIs via this.
