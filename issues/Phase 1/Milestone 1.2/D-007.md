# D-007: Implement model upload endpoint

## Description

The Data Repository must accept model uploads from SuperNova (trained model output) and potentially from operators. The upload flow: client streams model files → Data Repository → ORAS push to Harbor → metadata record in Postgres. D-006 provides the ORAS layer; D-005 provides the schema.

## Goal

- Implement `POST /api/models/{name}/versions` (or `POST /api/models/{name}/versions` with version in body). Accept streaming upload (multipart or chunked body).
- Flow: (1) Receive stream. (2) Write to temp file/dir. (3) ORAS push to Harbor (`imgrepo.damit.hu/supernova/models/{name}:{version}`). (4) Create/update `artifact_versions` and `artifacts` in Postgres. (5) Return version ID and Harbor ref.
- Version: auto-increment (v1, v2, …) or client-specified (e.g. `2026-03`). Support both.
- Metadata: store `size_bytes`, `checksum` (SHA-256 of blob). Optional: `training_config`, `eval_metrics`, `lineage` in request body, stored in `artifact_versions.metadata` JSONB.
- Streaming: do not load entire model into memory. Stream to temp, then push. For very large models, consider chunked upload or direct-to-Harbor if ORAS supports it.
- Return 201 with `{"version": "v1", "harbor_ref": "...", "size_bytes": ...}`.

## Additional Notes

- Repo: `data-repository` at `/mnt/nvme/AI/damit-aiops/data-repository`
- Depends on D-005 (schema), D-006 (ORAS layer).
