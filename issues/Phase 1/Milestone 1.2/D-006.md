# D-006: Implement ORAS integration layer

## Description

The Data Repository stores blobs in Harbor via ORAS. D-003 validated oras-py. This issue implements a reusable wrapper module that handles authentication, streaming, error handling, and custom OCI media types. All upload/download endpoints (D-007, D-008, D-009, D-010) will use this layer.

Harbor URL: `imgrepo.damit.hu`. Models go to `supernova/models`, datasets to `supernova/datasets`. Custom media types distinguish artifact types for future tooling.

## Goal

- Create `app/oras/` or `app/storage/` module with:
  - **`OrasClient`** (or `HarborStorage`): wrapper around oras-py. Config: Harbor URL, credentials (from env/secret).
  - **`push_artifact(files_or_stream, target_ref, media_type)`**: Push files/directory to `target_ref` (e.g. `imgrepo.damit.hu/supernova/models/iris-osl:v3`). Support streaming for large files.
  - **`pull_artifact(ref, output_path)`**: Pull artifact to local path. Return checksum if available.
  - **Authentication**: Login on init or per-request. Handle token expiry, retries.
  - **Error handling**: Registry unreachable, auth failure, 404, 413 (size limit). Raise typed exceptions for API layer to map to HTTP status.
- Define custom OCI media types: `application/vnd.supernova.model.v1`, `application/vnd.supernova.dataset.v1`. Use when pushing; document for consumers.
- Support both single-file and directory (multi-layer) artifacts. For HuggingFace models (many files), pack as tar or push as multi-layer OCI.
- Document the module API and usage patterns for D-007/D-008 implementers.
