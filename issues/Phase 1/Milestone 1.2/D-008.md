# D-008: Implement model download endpoint

## Description

Clients (Solar Control, SuperNova step containers) need to download models from the Data Repository. The flow: client requests model by name and version → Data Repository looks up Harbor ref in Postgres → ORAS pull from Harbor → stream to client.

## Goal

- Implement `GET /api/models/{name}/versions/{version}/download`. Path params: `name`, `version` (or `latest` alias).
- Flow: (1) Resolve `name` + `version` to `artifact_versions` row. (2) Get `harbor_ref`. (3) ORAS pull from Harbor to temp (or stream directly if supported). (4) Stream response to client with `Content-Disposition: attachment; filename="..."` and appropriate `Content-Type`.
- Support `version=latest`: resolve to most recent version by `created_at`.
- Return 404 if model or version not found.
- Streaming: use FastAPI `StreamingResponse` or `FileResponse` to avoid loading full model into memory.
- Optional: support `Range` header for resumable downloads.

## Additional Notes

- Repo: `data-repository` at `/mnt/nvme/AI/damit-aiops/data-repository`
- Depends on D-006 (ORAS layer).
- D-014 (URI resolve) returns metadata and download URL; clients may call this endpoint directly. Solar Control's repo resolver (D-016) will use it to pull models to hosts.
