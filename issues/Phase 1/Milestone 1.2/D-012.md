# D-012: Implement version listing and management

## Description

Artifacts can have multiple versions (e.g. `iris-osl:v1`, `iris-osl:v2`, `iris-osl:v3`). Clients need to list versions, resolve `latest`, and manage version metadata. D-007/D-009 create versions; this issue adds listing and `latest` alias.

## Goal

- Implement `GET /api/models/{name}/versions`. Return list of versions with metadata: `version`, `created_at`, `size_bytes`, `checksum`, `training_config`, `eval_metrics` (if stored).
- Sort by `created_at` descending (newest first).
- Implement `latest` alias: `GET /api/models/{name}/versions/latest` or support `version=latest` in download endpoint. Resolve to most recent version.
- Auto-increment version numbers: if client does not specify version on upload, assign next (v1, v2, v3). Store in `artifact_versions.version`.
- Same for datasets: `GET /api/datasets/{name}/versions`.
- Optional: `DELETE /api/models/{name}/versions/{version}` to remove a version (delete from Postgres, optionally from Harbor). Document retention policy interaction (D-029).
