## Description

The public Solar status page shipped in #111 and is served at `/status`. Five follow-ups are needed on the page and its public summary: the two component sections are labelled and ordered backwards relative to what the names mean, message windows print in UTC instead of the reader's time zone, notice bodies render as plain text, long component names push the status label onto a second line, and the public payload exposes instance counts and intent phases that the page does not need.

## Goal

- **Aliases first, then Models:** `apps/solar-status/src/routes/+page.svelte` renders `summary.virtual_models` under the heading "Models" and `summary.aliases` under "Aliases". In product terms the virtual names (`core`, `wind`, ...) are the aliases and the concrete names (`deepseek-v4.1-flash-1017:552b`, ...) are the models, so swap both the labels and the section order: "Aliases" (`virtual_models`) first, then "Models" (`aliases`). Keep the API field names `virtual_models` and `aliases` unchanged – they are the internal contract, and renaming them would break the SPA and any other consumer.
- **Browser-local times:** `formatInstant` in `apps/solar-status/src/lib/status/types.ts` formats every message window with `toISOString()` and a literal " UTC". Format the start and end instants in the browser's own time zone with `Intl.DateTimeFormat`, keeping the current `YYYY-MM-DD HH:mm` shape and adding a short zone label (e.g. `2026-10-30 17:00 CET`). Keep the uptime bar tooltip labels on their UTC bucket day: a bar is a UTC day bucket, and shifting the boundary would label it with the previous or next day in some zones. `ssr = false` (`apps/solar-status/src/routes/+layout.ts`), so there is no server-render mismatch to worry about.
- **Markdown notice bodies:** `apps/solar-status/src/lib/components/MessageItem.svelte` renders `{message.body}` as plain text with `whitespace-pre-line`, so `**bold**`, lists, links and inline code show literally. Render bodies as sanitized markdown: `marked` for GFM parsing with `breaks: true` so existing single-newline notices keep their line breaks, and `DOMPurify` before `{@html}` because the page is public. Style the result with the already-installed `@tailwindcss/typography` plugin (`prose prose-invert`); `apps/solar-status/src/routes/layout.css` already imports the plugin but nothing uses it. Document that `body` accepts markdown in the `StatusMessageCreate`/`StatusMessageUpdate` model docstrings, the management route docstring and the Hungarian `apps/solar-status/README.md`.
- **Long names keep the status on line one:** `apps/solar-status/src/lib/components/ComponentRow.svelte` lays the row out as `flex flex-wrap`, so a long name like `deepseek-v4.1-flash-1017:552b` fills the line and pushes the `StatusBadge` onto the next line. Pin the badge with `shrink-0`, give the text column `min-w-0`/`flex-1`, and truncate the name (and the detail) with the full text in a `title` attribute. Apply it to every section – the Instances rows have the same shape.
- **Trim the public payload:** `AliasStatus` in `apps/solar-control/app/models/status.py` publishes `instances_running`, `instances_total` and `intent_phase` on the unauthenticated `/api/status`, and the SPA prints them as `x/y instances running` and an `Intent: <phase>` chip. Drop the three fields from the public response and the matching `detail`/`phase` props in `apps/solar-status/src/lib/status/types.ts` and `ComponentRow.svelte`. Keep `_intent_phase()` and the running/total counting internal in `apps/solar-control/app/services/status_summary.py`: the intent map still decides which aliases exist and which instances are intent-managed, and `availability` still derives from the counts.
- **Tests:** update `apps/solar-status/src/routes/+page.svelte.spec.ts` for the swapped headings and order, the local-time windows and the removed count/phase text; add a `MessageItem` spec covering bold, list, link, inline code and a stripped `<script>` payload; add a long-name row test asserting the badge stays in the first line (`shrink-0` on the badge, `truncate` + `title` on the name). Update `apps/solar-control/tests/test_status_route.py` to assert the three fields are gone while the orphan alias still surfaces with `availability: "down"` and the virtual-model degradation case still reports `degraded`.
- **Out of scope:** no changes to the sampler, uptime math or history retention; no message CRUD API change beyond documenting markdown; no new page sections or visual redesign; no notification or subscription features; no gateway routing or `/webui` dashboard changes.

## Additional notes

- Current live example (prod `GET /api/status`): `virtual_models` holds `core` and `wind`; `aliases` holds `deepseek-v4.1-flash-1017:552b`, `embeddinggemma-2`, `qwen3.6:35b` and others. The page renders "Models" (`core`, `wind`) above "Aliases" (`deepseek-v4.1-flash-1017:552b`, ...), which is the inversion.
- Grounding: `apps/solar-status/src/routes/+page.svelte:95-128`, `apps/solar-status/src/lib/status/types.ts:113-122`, `apps/solar-status/src/lib/components/ComponentRow.svelte:21-35`, `apps/solar-status/src/lib/components/MessageItem.svelte:8-13`, `apps/solar-control/app/models/status.py:48-54`, `apps/solar-control/app/services/status_summary.py:234-241, 303-330`.
- Markdown dependencies: `marked` and `dompurify` are new runtime dependencies of `apps/solar-status`; update the root `pnpm-lock.yaml`. `@tailwindcss/typography` is already in `apps/solar-status/package.json` and imported in `layout.css`, so the prose styling needs no new package.
- Timezone tests must not depend on the CI runner's zone: give the formatter an optional `timeZone` argument and assert with an explicit `Europe/Budapest` in the unit test, or pin `TZ` in `vite.config.ts`. A UTC runner would otherwise pass the old and the new implementation alike.
- `body` is a `Text` column with only `min_length=1` (`apps/solar-control/app/models/status_message.py`), so markdown needs no schema or migration change. Map markdown headings to `h3` (or leave them out) so a notice cannot render a second `h1` under the page title; leave images out of the allowed markdown, since a public page should not load third-party images.
- Removing `instances_running`/`instances_total`/`intent_phase` is a public response contract change. The bundled SPA is the only consumer in the repo and ships with this issue; counts and intent phases stay available on the management API (`/api/instances`, `/api/intents`) for operators.
- Verify in a real browser (house rule for UI changes): a long alias at a narrow viewport and at the 3440×1440 ultrawide, a markdown notice with bold, list and link, and a message window that crosses midnight in a non-UTC zone.
